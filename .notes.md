# Strict-flip root R2: implicit-return + `-> Type` annotation

## Bug
Strict-mode checker emitted `Function 'f' must return a value` for VALID
implicit returns when the fn carried a `-> Type` annotation:
- trailing expression body: `fn zero() -> int { 0 }`
- trailing if/else body:     `fn pick(b: bool) -> int { if b { 1 } else { 2 } }`

The same bodies without the annotation type-checked fine; baseline
(ReliableOnly) ran the programs correctly. Strict's structural return-presence
check (`has_return_statement`) only recognized explicit `Statement::Return`,
ignoring implicit (trailing-expression / if-else block-expression) returns.

## Root
`crates/shape-runtime/src/type_system/checker.rs`
- `check_item` (Item::Function arm, ~line 392): gated `MissingReturn` only on
  `!has_return_statement(body)`.
- `has_return_statement` (~line 416): explicit-`Return`-only; never treats a
  trailing expression or value-producing if/else as a return.

## Fix (type_system only — focused, NOT a blanket suppression)
Added `block_has_implicit_return(stmts)` + `branch_produces_value(stmts)` and
extended the `MissingReturn` guard to
`!has_return_statement(body) && !block_has_implicit_return(body)`.

`block_has_implicit_return` inspects the block's LAST statement:
- trailing `Statement::Expression` -> value-producing (covers `{ 0 }`,
  `{ match .. }`, `{ loop { break v } }`).
- trailing `Statement::Return` -> value-producing.
- trailing `Statement::If` with BOTH branches value-producing (recursive;
  each branch via implicit return OR all-paths explicit return). Bare `if`
  without `else` -> false (else path falls through; still errors).

Mirrors `infer_callable_return_type`'s treatment of the final statement as the
implicit return. Does NOT validate the produced TYPE — the inference engine
still rejects wrong-typed implicit returns, so genuine bugs still error.

## Why not a broad suppression
- Genuinely-wrong bodies still error:
  - body ending in `let` (void) -> `void is not compatible with int` (inference)
  - bare `if` without else -> `block_has_implicit_return` returns false
- True positives preserved:
  - non-bool-in-if condition `if x { 1 } else { 2 }` (x: int)
    -> `int is not compatible with bool` (REJECTED)
  - branch type mismatch `if b { 1 } else { "two" }` (-> int)
    -> `int is not compatible with string` (REJECTED)
