# Frozen baseline for `just check-no-dynamic`.
#
# Format: <limit><tab><ripgrep PCRE pattern><tab><note>
#
# Rules:
#   - Lower a limit when a count decreases (deletion progress).
#   - Never raise a limit. Once a row reaches 0 it stays at 0 forever.
#   - Adding a forbidden pattern is fine — start it at the current count.
#   - Scope is enforced by scripts/check-no-dynamic.sh: crates bin tools
#     extensions, minus *.md (prose under crates/ is not code — see the script).
#
# A SYMBOL ROW PROVES A NAME IS GONE, NOT THAT A BEHAVIOR IS GONE (#256).
#
# The gate's founding assumption is that a forbidden construct must be SPELLED
# to exist. It need not be. `emit_index_to_i64` (mir_compiler/places.rs, since
# deleted) rebuilt the deleted `is_tagged` dispatch inline in Cranelift IR —
# an iconst of 0xFFF8_0000_0000_0000, an unsigned icmp, a select — calling no
# helper and naming no ratcheted symbol. Every symbol row here passed while it
# stood. Renaming its local variable would have made it invisible to the one
# row that caught it by luck.
#
# So: when you add a row for a deletion, ask whether the construct is
# expressible from primitives. Rows covering a deleted FUNCTION are mostly
# safe — the name is the thing. Rows covering a deleted DISPATCH PATTERN are
# the exposed class, and need a shape-level or bit-pattern companion row
# alongside the name row. Rows 53-54 are the worked example.
#
# A limit above the measured count is SLACK, and a regression can hide inside
# it: delete a comment mention, add a live call, count unchanged, gate green.
# Shrink a row the moment it can shrink. Where the residue is comment prose,
# prefer the `^(?!\s*(//|///|\*)).*` exemption idiom and a limit that counts
# only code lines — it makes the row bite on the FIRST live reintroduction
# instead of the twelfth, and it stops the gate punishing the by-name
# documentation of deleted code that CLAUDE.md §Forbidden Patterns requires.
#
# Established 2026-05-07 on bulldozer-strictly-typed @ 7bab206.
