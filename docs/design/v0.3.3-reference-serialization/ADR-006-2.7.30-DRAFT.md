# ADR-006 §2.7.30 — Reference escape→RC promotion + snapshot reference-serialization (narrow floor)

**Status:** SUPERVISOR DRAFT for user/strategic-owner text-ratify (2026-05-29). Drafts-file mechanism — apply to `docs/adr/006-value-and-memory-model.md` after ratify, with `// ADR-006 §2.7.30` marker comments at the named code touchpoints.

**Scope of THIS amendment:** the v0.3.3 NARROW FLOOR only. Broad container/closure-env escape flips + live-continuation resume are explicitly OUT (v0.3.4+, see §2.7.30.6). This amendment must not be read as authorizing them.

---

## 2.7.30.1 Context

Today references are escape-aware and SOUND but *reject* long-lived escapes: a reference that outlives its referent's scope is a B0003 `ReferenceEscape` compile error (`mir/solver.rs:1146-1160`). The escape→RC promotion machinery (§2.7.8 / `storage_planning.rs:928-959`) already promotes referents to RC'd heap for the *other* escape kinds (closure-capture, cross-task, store-into-shared). References are the one escape kind that rejects instead of promoting — so a long-lived reference cannot exist, and therefore cannot be snapshotted, which leaves `snapshot()` incomplete for programs that bind references (user 2026-05-29: release-blocking for v0.3.3).

Two adversarial design rounds established: (round 1) the obvious non-owning `RefTarget::Local`-coordinate carrier is a **use-after-free** on `return &local` (`return_value_inner→truncate_stack`, `control_flow/mod.rs:778` + `stack.rs:929-935`, drops the sole owning share at frame-pop while the deref path reads freed bits with the frozen MakeRef-time kind); (round 2) the *broad* flip + *live continuation* carry unresolved UAF/double-free/cross-instance-`&mut` breaks and are not soundly landable in v0.3.3.

## 2.7.30.2 Decision — the heap-owning PromotedCell carrier

When a reference escapes via a flipped sink (§2.7.30.3), the **referent** is promoted to an RC'd `SharedCell` and the reference holds an owning `Arc` share via a new carrier:

```rust
// shape-value/src/reference.rs — new RefTarget variant
RefTarget::PromotedCell { cell: Arc<SharedCell> }
```

The owning share keeps the referent alive past the referent's lexical frame-pop (refcount ≥ 1 while any reference exists) → **frame-independent identity**. This is the only memory-safe carrier; the non-owning-coordinate alternative is the proven round-1 UAF and is FORBIDDEN.

- The carrier reuses `SharedCell` (the existing interior-mutability cell), not a new heap type.
- Deref reads/writes go through the cell (unwrap-the-Arc), never a raw frozen-kind slot read. The `RefTarget::Local` fast-path (`variables/mod.rs:2997`) remains for *non-escaping* references only; a reference whose referent was promoted resolves via the `PromotedCell` arm.
- The double-decrement concern is the cluster-1.5 share-accounting pattern (explicit `clone_with_kind` retain before claim), NOT grounds to choose a non-owning carrier.

## 2.7.30.3 Decision — reference-escape is the fourth escape→RC promotion trigger (NARROW)

`detect_escape_status` / `decide_slot_storage` add reference-escape as a promotion trigger **for exactly two loan sinks**:

- `LoanSinkKind::ReturnSlot` (returning `&x`)
- `LoanSinkKind::ModuleBindingStore` (`let r = &x` at module/script scope)

On these sinks, the escaping reference's **referent** transitions `Direct → SharedCow`/`UniqueHeap` (promoted, RC'd) instead of the binding emitting B0003. All OTHER sinks **stay hard-rejecting** in v0.3.3:

- `LoanSinkKind::ClosureEnv` (B0003-closure) — STAYS REJECT (v0.3.4; UAF without further design)
- container store (B0004) — STAYS REJECT (v0.3.4; KL-4 provenance-double-free unresolved + cycle-UAF)
- task-boundary (B0006/B0012) — STAYS REJECT (cross-task coherence)
- TypedField field-escape — STAYS REJECT

Residual genuine-dangling still rejects: a reference to a **moved** value (the independent move pass / B0005) and any case where promotion cannot guarantee referent liveness. `&mut` exclusivity (B0001) is UNCHANGED — a second `&mut` to a promoted referent still rejects.

## 2.7.30.4 Decision — Drop defers to reference lifetime

A referent with `impl Drop` whose reference escapes has its Drop **deferred** from lexical scope to the escaping reference's lifetime (program/module lifetime for `ModuleBindingStore`). This is required for soundness (the referent must outlive every reference to it) and is an **observable Drop-ordering change** — it requires a CLAUDE.md note (user-ratified 2026-05-29).

## 2.7.30.5 Decision — snapshot reference-serialization (replay-only)

References serialize via an **identity-handle + restore-time identity-map** (the same mechanism as the SharedCell snapshot arm):

- New `SerializableVMValue` arm replaces the identity-free `ReferenceOpaque` (`snapshot.rs:1104`): a reference serializes as a handle to its (promoted, RC'd) referent + the `is_mut` mode bit (CARRIED, reserved-not-read in v0.3.3).
- A `heap_referents` identity side-table (NEW — currently 0 hits in tree) maps original-pointer → restored-pointer; on restore, aliased references dedupe to ONE restored referent. `from_snapshot` becomes allocate-then-link (currently single-pass) with a cycle/depth guard.
- **REPLAY-ONLY:** a resumed VM replays the same MIR; no live-loan continuation on a resumed VM holding restored loans (v0.3.4). The `is_mut` bit is carried-not-dropped so the v0.4 runtime-loan re-establishment has it. This sidesteps the round-2 BREAK-1 (multi-instance `&mut`) and BREAK-2 (NLL-dead-loan-resurrection) breaks, which are live-continuation problems.

## 2.7.30.6 Scope boundary (binding)

- **IN (v0.3.3):** ReturnSlot + ModuleBinding reference-escape→promote; PromotedCell carrier; deferred-Drop; replay-only snapshot ref-serialization with `heap_referents` identity-map.
- **OUT (v0.3.4+, per-sub-feature soundness-gated):** broad container-escape flip (needs KL-4 provenance-double-free design + points-to acyclicity), closure-env flip, live-continuation resume (needs runtime-loan re-establishment), and cross-instance/cross-node `&mut` coherence (the distributed-execution design — needs runtime `is_mut` + consumed-snapshot tracking).

## 2.7.30.7 Forbidden (per CLAUDE.md §Forbidden)

- NO non-owning reference carrier (the proven UAF). PromotedCell owns its share.
- NO new `ValueWord`-shape carrier / "serialization helper" / "reference marshal bridge" — references serialize via the parallel `Vec<u64>`+`Vec<NativeKind>` track (§2.7.7) + the identity-map. NO Bool-default; NO raw-pointer-token (the KL-4 double-free path).
- NO silent broad-scope creep: the flipped-sink set is exactly the two named in §2.7.30.3; widening requires a further amendment with its own soundness design.

## 2.7.30.8 c6-binop-ref guard CO-LANDS with the flip (premise CORRECTED 2026-05-29, run-verified)

The original "widen c6 against a live-at-HEAD `EXIT=139`, land FIRST" premise is **FALSIFIED**. Run-verify at HEAD: reference-typed params/returns/method-returns do NOT parse (`fn f(r: &int)` / `-> &int` / `&mut int` → E0001), and every direct ref-producing form in a binop (`&x`, `&p.x`, `&a[i]`) is ALREADY caught by the existing c6 semantic reject ("cannot apply binary operator to a reference operand"); `let r=&x` is inference/B0003-rejected. So `make()+1` where `make()->&int` is **inexpressible at HEAD** — there is no live segfault to guard against.

The ref-typed-operand segfault surface is **created BY the flip** (which, with the grammar change in §2.7.30.9, first makes `&T` returns/params/bindings expressible). Therefore the widened c6 guard **CO-LANDS with the narrow-floor flip, not before it**: the single change that makes ref-typed operands expressible also adds the widened reject + a test proving it catches `make()+1` / `make()->&int`. No standalone precursor step.

(Investigate-not-assert: the audit's c6-binop-ref `EXIT=139` may have been a ReliableOnly type-error-suppression manifestation — `f(&a)` passing `&a` to an `int` param, suppressed under ReliableOnly — which would AUTO-CLOSE under the strict flip rather than being a distinct binop-ref gap. Re-check the original `f(&a)+&a` repro once the strict flip lands.)

## 2.7.30.9 Grammar change is in scope (NEW finding 2026-05-29)

The ReturnSlot flip (`return &x`) requires the return type `-> &int` to be expressible, and `&T` does NOT parse in type-annotation position at HEAD (param + return). The narrow-floor build therefore **includes a grammar/parser change** making `&T` parse in param + return type positions. Bounded but in-scope — and it is precisely the change that brings the ref-typed-operand surface into existence (hence §2.7.30.8's co-landing).
