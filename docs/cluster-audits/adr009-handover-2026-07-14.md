## 3. C1 (#12) — REJECTED, and why it matters

Branch `adr009/c1` @ `34c57f5c` implements a `capture(...)` head-form inside
generated closures, stripped from the AST before the type checker, with the
declared pack recorded in a **span-keyed side table**. A four-lens adversarial
review (each finding double-refuted) returned **unanimous REWORK, 19 confirmed
findings, 3 critical**. Full verdict + rework spec: issue #12.

The three that make it unmergeable:

1. **The declared Mode is validated, then discarded.** Emission still runs the
   Wave-46 *inference* selector (`closures.rs:3658-3745`); it never reads the
   declared pack. `capture(x)` and `capture(&x)` compile to byte-identical
   bytecode. The declare-and-validate conversion is cosmetic — inference is
   still the authority.
2. **The pack table cannot identify a closure.** Keyed on `Span{start,end}`
   byte offsets with no source identity, while generated AST is parsed from
   standalone snippets starting at offset 0 (or `DUMMY`). Collisions let a
   closure with *no* declaration pick up a foreign pack and be silently accepted
   **with an undeclared implicit capture** — the exact thing the gate exists to
   stop.
3. **`CaptureDescriptor<Sig,I,T,Mode>` — the ticket's headline artifact — is
   dead code** (module-wide `#![allow(dead_code)]`). The live carrier is
   `DeclaredCapture { name: String }`, resolved and matched by **source name**.
   That is the name-based identity ADR-009 exists to eliminate.

This is the classic defection shape this codebase has a documented history of
(CLAUDE.md §Forbidden Patterns): a new mechanism that *looks* typed while the
old untyped path remains the real authority, plus a "follow-up" deferral for the
flagship code path. **Do not merge it as-is.** The rework spec on #12 is binding:
structural identity on the live path, the declared pack must *drive* emission
(one selector, asserted), closure identity from the existing `ExpansionIdentity`
machinery, generated `extend` method bodies in scope or named-rejected, and
proofs per accepted mode including a heap capture with teardown balance and a
JIT proof that cannot pass under `[jit-fallback]` deopt.

Consider a spelling that needs **no strip at all** — the originally-ruled
`Expr::FunctionExpr` capture field, or a comptime builder that never enters the
checked AST — which removes this entire failure class.

## 4. How the work is run (the machinery that works)

**Worktrees** (pre-created, warm target dirs — Agent `isolation:worktree` is
unreliable here):
`../shape-adr009-a1`, `../shape-adr009-a3`, `../shape-adr009-b2`,
`../shape-adr009-d1`. Directory names no longer match branch names; check
`git -C <wt> branch --show-current`.

**Workflow scripts** (session scratchpad, copy forward and edit `TICKETS` +
`BASE`): the slim all-Opus pipeline is
`adr009-wave5-slim-v8.js` (latest). Shape: 1 scout → 1 plan (≤4 slices) →
sequential TDD slices under a global build-lane mutex → gate → 1 combined-axis
reviewer → 1 refuter per finding → ≤1 fix round → squash-close. ~10 agents,
~1M tokens per ticket. Stack dependent tickets on ONE branch (B6→B5→B7 did this)
— it eliminates cross-branch merge conflicts entirely.

**Model policy (user ruling):** every workflow agent runs `model: 'opus'`;
the supervising main agent stays Fable and performs the cross-model
verification itself at integration (independent gates, merge review,
positive-claim spot-checks).

**Build lane (hard):** exactly one cargo command at a time, always wrapped:

```
systemd-run --user --wait --collect --pipe -p MemorySwapMax=0 \
  -p MemoryMax=12G -p TasksMax=256 -p WorkingDirectory=<worktree> \
  --setenv=CARGO_BUILD_JOBS=2 --setenv=PATH="$PATH" \
  direnv exec /home/dev/dev/shape-lang cargo <args>
```

Memory budget: keep `Σ(MemoryMax × concurrent tickets) ≤ 36G` (host has ~42G
available). Workflow agents must run builds **foreground** with
`timeout: 600000` and retry on timeout — a subagent that backgrounds a command
and ends its turn is killed before it can report.

**Supervisor loop per wave:** independent combined gate on the integration
branch → merge to `main` behind the stash cycle (§5) → verify the overlay
compiles → push → close issues → dispatch next frontier.

**Standing gate battery** (what "green" means here):
`shape-vm --lib compiler::comptime{,_builtins}` + `compiler::functions_annotations`,
`shape-ast --lib`, `shape-runtime --lib comptime*`, `shape-lsp --lib`,
`shape-test --test comptime` (`--test-threads=2`), `--test annotations_comptime`
(`--test-threads=1`), `--test lsp`, `scripts/check-no-dynamic.sh`, plus
`cargo check -p … --all-targets`. Never run the full bulk shape-test suite in
one command (known hang).

## 5. The concurrent wave in the main worktree — read before merging anything

`~/dev/shape-lang/shape` (main worktree) carries **~130 modified + ~137
untracked files of someone else's uncommitted work** (a `SetParamTypeExpr`
comptime directive, await-payload typing, `remote::call` elaboration, and more).
It is NOT mine and must not be committed or reverted.

Merging to `main` therefore uses a **stash cycle**: compute the overlap between
the merge's file list and the dirty set, `git stash push -- <overlap>`, merge,
`git stash pop`, reconcile, verify the overlay compiles, then push **only the
merge**. Traps learned the hard way:

- `git stash pop` **pre-stages the index** — always `git reset` and commit
  *specific paths*, never `git add -A`/bare commit. (One docs commit swept 15
  WIP files into `main`; it had to be reverted in `5697ff3b`.)
- Full pre-merge backup patches are in the session scratchpad
  (`main-dirty-full-backup-w{3,4,5}.patch`).

**Two live cross-wave collisions I reconciled in *their* overlay (uncommitted,
flagged for that wave's owner):**

1. Their `remote::call` elaboration resolved names through
   `self.function_aliases` — the `__original__`→shadow map **E3/U11 deleted on
   purpose** (a user-spelled `__original__` must no longer resolve). The alias
   hop can never fire post-E3; I dropped it with an in-place comment. If that
   wave needs `remote::call` on the pre-annotation original from inside a
   `replace body`, it must route through the typed `ctx.original` capability
   (`compiler/original_body_rewrite.rs`).
2. Their new `Statement::SetParamTypeExpr` variant needs an arm in E3's new
   exhaustive match in `original_body_rewrite.rs` (added to the clone-verbatim
   comptime-directive group). CLAUDE.md's Exhaustive Match Rule — expect more of
   these as that wave lands.
