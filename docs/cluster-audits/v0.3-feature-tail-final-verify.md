## sf-NEW = 9 — net-new red (PASS at base @36d917b6, FAIL at HEAD, both deterministic in isolation)

Cluster: **map/orderBy/forEach closure-RETURN element-type over-constraint.**
Introduced by the feature-tail result-element-stamp commits (`f45f86cd`
"stamp result element = closure RETURN type", `26a6fe9d`, `2071d5a1`,
`b9a9d18e`). The stamp tightened `Array<int> != Array<number>` correctly for
the kind-changing map case but emits a *conflicting* residual constraint on
three benign paths.

Two solver signatures, both `Semantic error: Could not solve type constraints`:

### (a) `int is not compatible with number` — 7 tests
Lossless int→number map / numeric comparator. The result-element stamp ties
the map output to the closure return (`number`) while a residual constraint
still ties it to the source element (`int`).
- `arrays_vectors::stress_map_filter::test_map_to_float` — `[1,2,3].map(|x| x * 1.5)`
- `arrays_vectors::methods::array_sort_with_comparator`
- `arrays_vectors::stress_map_filter::test_sort_with_comparator`
- `arrays_vectors::stress_map_filter::test_sort_descending_comparator`
- `arrays_vectors::stress_sort_find::test_order_by_identity` — `[3,1,2].orderBy(|x| x)`
- `arrays_vectors::stress_sort_find::test_order_by_descending`
- `arrays_vectors::stress_sort_find::test_order_by_negative_key`

### (b) `void is not compatible with void` — 2 tests
forEach with a unit-returning closure; the stamp path emits a degenerate
self-unification on the (void) forEach result element that the solver rejects.
- `arrays_vectors::transforms::array_foreach_prints_each`
- `closures_hof::array_methods::array_foreach_output` — `[1,2,3].forEach(|x| print(x))`

NOTE: `stress_sort_find::test_order_by_identity` (and siblings) assert
`.expect_number(1.0)` on an `int` array — at base these passed via the old
looser unification; under the new stamp + strict-flip the int/number split is
enforced, so part of this cluster may resolve to a TEST-rebaseline rather than
a checker fix. The forEach `void` family (b) is unambiguously a checker bug
(spurious constraint) and must be fixed in the stamp path, not rebaselined.
