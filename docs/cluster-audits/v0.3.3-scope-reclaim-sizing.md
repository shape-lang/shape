## Net picture: riders vs. net-new

### Families that RIDE an already-counted keystone (§2.7.4) — ZERO net-new effort

- **w17.3-4-marshal** — the true marshal core (~30 tests: stdlib_json 14 + stdlib_regex 5 +
  the stdlib_modules marshal half) is ONE `project_typed_return` per-arm KindedSlot projection
  seam = **§2.7.4 keystone 1**, clears as a side-effect. The remaining "~110" the label sweeps
  in is mislabeled overlap onto V3-S5 construction + strict-flip inference (double-labeled, not
  double-effort). **Net-new = 0.**

- **w18-lsp content-rendering half** (~12, a root-cause rollup, not a discrete test file) — the
  user-value→ContentNode render/output-adapter surface is the same `slot_extract_content` /
  print-path marshal the §2.7.4 rebuild must do. **Rides §2.7.4.** (The 2 comptime-extend "LSP"
  tests ride V3-S5.) Only the **LSP trait-resolution wiring seam (~10 tests)** is net-new.

### Net-new families (genuine new effort, do NOT clear from a counted keystone)

- **v3s5-ckpt56-op-new-array** — the V3-S5 TypedArray\<T\> per-T monomorphization rebuild. This
  is its OWN keystone, NOT §2.7.4 / strict-flip / ref-ser. **3 net-new seams**: (1) construction
  build-path (`op_new_array` / `op_new_typed_array` over the flat-struct carrier), (2) the
  ~206-reference / 11-public-handler consumer-method receiver-recovery rewrite, (3) per-T
  element stringification primitives (`joinStr`). Effort **L** (multi-checkpoint carrier
  migration). Drops to M if empty-literal-inference (W16.2-C) and W17.3-4 anon-object
  construction are booked under their own families.

- **v3s5-ckpt23-consumer-cascade** — shares the V3-S5 carrier with the family above. **2 net-new
  seams**: (1) per-element-kind consumer-handler rebuild (bool + string sibling modules + PHF
  rewiring + V2ElemType::String arm), (2) the `op_new_array(0)` empty/untyped construction seam.
  **If the V3-S5 construction keystone is booked once (under ckpt-56), this family's net-new
  collapses to 1 seam (consumer handlers only) and effort drops to S.** Effort **M** standalone.

- **destructuring** — discrete destructure-path compiler gap, distinct from all three counted
  keystones. **3 net-new seams**: (1) binder FieldType-propagation [BIG — clears ~all ~27 of the
  largest sub-cluster], (2) VM `type_check_kinded` missing object/array Basic arms, (3) array
  REST `[a, ...rest]` genuinely unimplemented. 6 tail tests ride V3-S5/W17 — net those out.
  Effort **M** (5-6 files across compiler+inference+VM, must land atomically).

- **comptime-trait** — does NOT collapse (genuinely 3 distinct comptime seams). **3 net-new
  seams**: (1) const-initializer comptime-eval gate [dominant, 44 tests — lift/widen the gate so
  the existing comptime mini-VM evaluates fn-calls/arithmetic/type_info/implements/build_config],
  (2) comptime-field type registration (6 tests — `type X { comptime field }` mis-registered as
  enum), (3) annotation-definition registration (verified live: `@annotation`/`@before`/`@traced`
  do not register). Up to ~20 op_new_array tests ride the already-fixed V3-S5 keystone. Effort
  **M**.

- **hashmap-rebuild** — does NOT collapse. **2 net-new seams**: (1) per-V HashMap
  monomorphization rebuild (~38 tests — re-introduce per-K / per-V kind handling at the
  `Arc<HashMapKindedRef>` carrier + wire receiver-recovery into closure `|k,v|` inference),
  (2) the W13 mutation contract (~6 tests — `.set()`/`.delete()` now mutate-receiver → `let m`

  (keys/values/entries/toArray + op_new_array) ride V3-S5. Strict-flip check done: all 65 are
  RUNTIME SR, none are the checker-FP class `7c37fe40` fixed. Effort **M**.

- **w18-lsp (LSP trait-resolution half)** — the single genuinely net-new LSP seam (~10 tests):
  consistent trait-resolution wiring across hover/completion/code-lens/goto reading the existing

## Net picture / re-projection

- **761 SCOPE-RECLAIM failures = 13 net-new fix-seams.**
- **2 of 7 families ride already-counted keystones** (w17.3-4-marshal fully → §2.7.4; w18-lsp
  content half → §2.7.4) = those slices are **zero new effort**.
- The **dominant net-new keystone is V3-S5 TypedArray\<T\> construction+consumer rebuild** (the
  two ckpt families, ~520 tests, 4 seams) — it is NOT one of the three previously-counted
  keystones, so it is honestly new work and must be carried in the v0.3.3 projection.
- **3 families do NOT collapse** (comptime-trait, hashmap-rebuild, w18-lsp) — genuinely
  multi-seam, not the cycle's textbook 1-seam pattern. The other 4 do collapse to a dominant
  seam each.

### Effort range (NET-NEW work only)

- V3-S5 ckpt-56 (L) + ckpt-23 consumer (S/M): ~3-5 sessions (one carrier migration, multi-ckpt).
- destructuring (M): ~1-2 sessions.
- comptime-trait (M): ~1-2 sessions.
- hashmap-rebuild (M): ~1-2 sessions.
- w18-lsp LSP-trait half (S-M): ~0.5-1 session.

**Net-new total: ~7-11 sessions.** (The §2.7.4 and strict-flip keystone work is counted
separately and is NOT in this range.)
