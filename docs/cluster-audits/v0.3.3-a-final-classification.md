## 2. GATE SIGNAL

> **fp_regression_total = 30**
>
> A-final requires this to be **0**. It is **30**, so A-final does **NOT** pass. Each FP is a checker over-rejection of valid code; they collapse to **~10 checker roots**. The top 2 roots (let-generalization + collection-dispatch) account for **15 of 30**.

The 30 genuine FP_REGRESSIONs, grouped by likely checker root (fix the root, not the test):

### Root A — untyped-fn-return / HM let-generalization gap (11)
The dominant root. An unconstrained fn-return type var is not generalized to a generic param; `fn f() { None }` / `fn f() { Err(..) }` / bodies whose return is shaped only at the call site are rejected `Could not infer generic return type for '<fn>'` / `Could not infer generic type arguments for 'Option'|'Result'|'Vec'`. Per `project_let_generalization.md` (user ruling 2026-05-31) these are **valid Shape** — the unconstrained return tyvar generalizes (`fn get_none(){None}` ⇒ `fn get_none<T>()->Option<T>`).
- `stress_recursion::test_function_returns_none_explicitly` — **the exact user-ruled binder** `fn get_none(){return None}`
- `stress_option::null_coalesce_with_fn_returning_null` (`fn get_val(){return None}`)
- `stress_propagation::error_propagation_rewrap` (`fn inner(){return Err(...)}`)
- `error_handling::edge_cases::edge_option_and_result_interop` (`fn find_user(){None}`)
- `error_handling::context_operator::context_plus_try_propagates_contextual_error` (`fn find_user(){None}`)
- `result::test_result_chained_err_short_circuit` (`fn step1(){Err(..)}` — unconstrained Err type-var E)
- `result::test_result_chained_ok` (`fn step1(){Ok(10)}` — unconstrained E)
- `stress_ok_err::chained_result_match_first_fails` (`fn step1(){return Err("fail")}` — unconstrained Ok payload)
- `pattern_based::test_complex_option_find_in_array` (`fn find_first(arr,pred){...Ok(item)...Err(...)}` — generic Result return)
- `pattern_based::test_complex_option_find_none` (same `find_first`)
- `stress_chained::test_fn_map_double` (`fn double_all(){[1,2,3].map(|x| x*2)}` — untyped fn-return Vec inference)

### Root B — collection-dispatch / bare-constructor `<K,V>` inference (4)
Bare `HashMap()` / `HashMap().set(...)` cannot infer `<K,V>` under strict mode (`Could not infer generic type arguments for 'HashMap'` / `HashMap<_oob,_oob> not compatible` / `Option args:[_oob] cannot have fields`). Valid code; the constructor's type args should be inferred from the subsequent `.set(k,v)` usage.
- `stress_operations::test_hashmap_returned_from_function`
- `stress_operations::test_hashmap_set_nested_hashmap_value`
- `stress_operations::test_hashmap_var_reassignment`
- `stress_creation::test_hashmap_created_in_function`

### Root C — module-member-resolution (namespaced call return mis-typed as the module) (3)
`crypto::fn(args)` (via `use std::core::crypto`) types the **result** as the module `crypto` itself, so `.length()` on the result → `Concrete(Reference(crypto)) cannot have fields` / `Method length not found on type crypto`. Breaks every `module::function().method()` chain. (Baseline failed these for a now-fixed queryable parse error; the strict-flip exposed the underlying module-resolution FP.)
- `stdlib_modules::crypto_tests::crypto_random_bytes_length`
- `stdlib_modules::crypto_tests::crypto_random_bytes_zero`
- `stdlib_crypto::hashing::crypto_hmac_sha256_produces_64_hex_chars`

### Root D — lost string `.length()` method dispatch (2)
`fn test()->int{"hello".length()}` → `Method 'length' not found on type 'string'`, but `length` IS a registered string PHF method (`method_registry.rs:902` → `string_methods::v2_string_len`). The strict-flip type-checker's string-method table is out of sync with the runtime registry.
- `stress_booleans_none::test_string_length_method`
- `stress_booleans_none::test_empty_string_length`

### Root E — int/number fixture mis-inference (2)
All-int programs (`Ok(10)`/`Ok(20)`/`0`, body `va+vb`, decl `-> int`) over-rejected `number is not compatible with int` — an integer literal is mis-inferred as `number`.
- `stress_ok_err::two_ok_results_matched`
- `stress_ok_err::one_ok_one_err_results_matched`

### Root F — width-cast assertion path (1)
`256 as i8` → `Cannot assert type int as i8`. `i8` IS a recognized width type (`semantic.rs:183`, `concrete_conv I8`, `constraints.rs:1448` has int↔i8 pairs) but the `as`-assertion path refuses it. Breaks explicit width casts to sized ints.
- `error_handling::diagnostics::width_cast_i8_always_valid`

### Root G — single-element Union not collapsed for Comparable (1)
`val > 10` → `Union([Basic(int)]) is not comparable`. The Comparable constraint (`constraints.rs:770`) accepts only `Concrete(Basic name)`, not a single-element `Union([int])` (produced by match-arm typing). A plainly-comparable int comparison is rejected.
- `error_handling::edge_cases::edge_result_as_if_condition_value`

### Root H — `?`-expanded default-error param vs `Result<T>` shorthand (1)
Fully-typed `Result<number>` + nested `?` → `Result<number, AnyError> is not compatible with Result<number>`. The `?`-expanded default-error param fails to unify with the `Result<T>` shorthand.
- `error_handling::edge_cases::edge_try_in_nested_function`

### Root I — no builtin-primitive Display impl for the where-clause solver (1)
`identity<T: Display>(42)` → `int does not implement trait Display`. `int` is formatable (print/fstring) but no builtin primitive `Display` impl is registered for the where-clause bound solver. (FP/TP boundary — called FP because the bound is satisfiable in spirit; flagged for review.)
- `generics::bounds::where_clause_with_function_body`

### Root J — singleton binding/dispatch losses (4)
- `imports_exports::test_export_pub_const_executes` — `pub const MAX_SIZE=1024; MAX_SIZE` → `Undefined variable: 'MAX_SIZE'`; strict path drops the pub-const module binding.
- `loops::cf_05_for_destructuring` — `for {x,y} in points` → `Undefined variable: 'x'`; object-destructuring pattern in for-loop loses its bindings.
- `multi_function::test_complex_string_pad_left` — `fn pad_left(s,total_len,pad_char)` string-concat body; strict over-constrains unannotated `param0` to numeric (from `result.length < total_len`) and rejects the string call site (unannotated-param numeric over-constraint).
- `trig::pi_constant_approximation` — valid user `acos(-1.0)`, but strict knocks out the untyped stdlib def `pub fn acos(x){__intrinsic_acos(x)}` → `Undefined function: 'acos'` (sibling `pow` identically affected). Same family as Root A but lands on stdlib registration.

> **Root note:** Roots A and J(`acos`) are the same underlying gap (untyped-fn / unconstrained type var) hitting user vs. stdlib registration. Implementing HM let-generalization on unconstrained fn-return/param tyvars likely clears Root A (11) + the `acos` singleton (1) = **12 of 30** in one fix. Root B (4) is the collection-dispatch inference root already partially landed on this branch (7c37fe40); the 4 here are the residual bare-constructor sites. The remaining ~14 are independent checker roots C–J.

## 4. LANG_TRUTHINESS (28) — deferred to the user truthiness ruling

Every one is a non-bool value used in an `if`/`while`/`&&`/`||`/`!` position, rejected `<type> is not compatible with bool`. These are NOT scored TP/FP — they hinge on a single language decision (does Shape coerce truthiness, or require an explicit bool condition?). Breakdown:
- `if <non-bool>` conditions: ints (`if 1`, `if 0`, `if -1`, `if 42`), numbers (`if 0.1`, `if -0.1`, `if 0.0`), strings (`if "x"`), Option (`if None`) — across `stress_if_basic`, `stress_integers`, `stress_booleans_none`, `stress_floats`.
- `!` / `&&` / `||` on int operands: `!1`, `!0`, `1 && true`, `0 && true`, `1 || false`, `0 || true`, `!None` — across `stress_logical`, `stress_booleans_none`.

If the user rules truthiness-coercion IN, all 28 become must-fix checker work (the condition checker must accept truthy types). If ruled OUT (explicit-bool-only), all 28 become TP_REBASELINE (migrate to negative suite). **No A-final gate impact either way** — the gate counts FP_REGRESSION only.
