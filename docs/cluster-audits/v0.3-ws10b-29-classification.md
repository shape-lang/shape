Failure-mode vocabulary: **crash** = process abort/SIGSEGV/SIGABRT;
**panic** = Rust `panic!`/`unwrap` on a test assertion; **wrong-result** =
program completes with an incorrect value; **VM-JIT divergence** = the two
tiers disagree; **spurious-reject** = valid Shape code rejected;
**clean-error** = honest `RuntimeError` / `NotImplemented(SURFACE)` /
`unimplemented!` surface-and-stop with no wrong-result.

Disposition rule: known-incorrect (crash / divergence / wrong-result /
memory-unsafety / silent-wrong-output / spurious-reject of valid code) →

## v0.3-gating items — precise fix-dispatch territory

Two distinct defect families classify as v0.3-gating. Each becomes new
fix-dispatch territory.

### GATING-A — REPL cross-cell persistence (7 tests, #22–28)

**Defect:** The shipped `shape repl` does not persist bindings across
consecutively-entered lines. `let a = 42` followed by `a` yields
`Undefined variable: a`; `type Point {...}` followed by `Point {...}`
yields `Unknown struct type 'Point'`. Reproduces in both `--mode vm` and
`--mode jit`.

**Why gating:** user-visible spurious-reject of valid Shape code — the
core REPL contract (a REPL that cannot reference its own prior line is
not a usable REPL).

**Confirmed-real, not a test artifact:** the 7 failing tests use a
test-local helper (`execute_repl_command` / direct
`BytecodeExecutor::execute_program`) rather than the real
`ShapeEngine::execute_repl` path — so the test failures alone were not
proof. Independently confirmed against the shipped release binary
(`printf '...' | ./target/release/shape repl`), VM and JIT both. The
defect is real.

**Territory hint (for the owning fix-workstream — not solved here, audit
only):** the real REPL routes `run_engine` → `ShapeEngine::execute_repl`
→ `execute_repl_inner` (`crates/shape-runtime/src/engine/execution.rs:130`).
Persistence wiring is `persistent_context_mut()` /
`ShapeEngine::init_repl` (`crates/shape-runtime/src/engine/mod.rs:169`).
The binding from one line's compiled module-scope to the next line's
compilation is the suspect surface. NOT itself a round-6 regression (the
WS-10 audit's exact set-diff against `3f227c63` proves the 7 failures
predate round-6); gating because it is a known-incorrect user-visible
defect under the no-known-incorrectness binding, independent of when it
was introduced.

### GATING-B — Option as-cast `Some`-path lift (2 tests, #13, #14)

**Defect:** `opt as number` / `opt as int` on a `Some(x)`-valued
`Option<T>` produces `RuntimeError("cannot convert kind Ptr(Option) to
number/int")` instead of element-wise lifting to `Some(x as U)`. The
`None`-valued companion path lifts correctly
(`option_none_as_number_lifts_to_none` passes). Confirmed in the release
binary, VM and JIT.

**Why gating:** asymmetric wrong behavior in compiled user code — a valid
cast the language intends to support (the `try_operator` test file's
"Option/Result lifting execution tests" section, and the sibling test
`invalid_infallible_cast_option_string_as_int_fails_at_runtime` whose
comment documents that the compiler *does* emit the lifting code) errors
on `Some` while succeeding on `None`. A None/Some inconsistency on the
same cast is a runtime correctness defect.

**Territory hint:** the as-cast lift executor receives an
`Ptr(Option)`-kinded value and routes it into the scalar
`__into_*`/`__try_into_*` conversion path rather than the Option-lift
path. Adjacent to (but distinct from) the documented generic-arg-erasure
constraint — the erasure explains *why* the compiler emits lifting code
for an Option local; the runtime defect is that the lift path does not
fire for `Some`. The owning fix-workstream should pin the as-cast
dispatch site that distinguishes scalar-cast from Option-lift.

## Cross-check against the WS-10 audit

The WS-10 audit (ITEM (b)) had classified all 29 as v0.4 — 8
TypedArrayData-cascade + 7 REPL-persistence + 4 arg-count-kind + 2
Queryable-parse + 2 DataTable-select + 2 Option-as-cast + 4 singletons —
"with the caveat that the REPL-persistence cluster (7 tests) and the
runtime-error-payload test ... warrant a targeted owning-workstream look
before v0.3 ship."

This WS-10b re-audit acts on that caveat by ground-truthing each one
against the shipped binary. The result: the REPL-persistence caveat is
upheld and sharpened — 7 tests are v0.3-GATING (confirmed user-visible in
`shape repl`), not v0.4. The Option-as-cast pair, which WS-10 placed in
v0.4 ("honest `RuntimeError`, no wrong-result"), is re-classified
v0.3-GATING: the None-passes/Some-fails asymmetry IS a wrong-result-class
inconsistency once the two halves are compared. The runtime-error-payload
test, also flagged by WS-10's caveat, is re-confirmed v0.4 — the error
itself surfaces; only the structured side-channel is empty (degraded
diagnostic, not a correctness failure). Net change vs WS-10: **9 of 29
move to v0.3-gating; 20 remain v0.4.**
