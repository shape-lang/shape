## §2 Tarpaulin invocation pattern

All commands below are paste-ready and were exercised empirically at HEAD
`e6b14a90` from inside the devenv shell. Each flag carries a stated
purpose; nothing is added "for safety".

### Line coverage (default)

```bash
cargo tarpaulin --workspace --lib --tests --skip-clean \
  --exclude shape-ext-python --exclude shape-ext-typescript \
  --timeout 240
```

Per-flag reasoning:

- `--workspace`: every workspace member tarpaulin can build (the bin-only
  crates `shape-viz-native` + `xtask` will skip with `error: no library
  targets found in package <name>` per §3 surface — that is a per-crate
  scope-out, not a workspace-wide failure).
- `--lib --tests`: matches the test tier 1+2 coverage shape (`just
  test-fast` + `just test`). Integration tests at `tools/shape-test/tests/`
  are `--tests` targets in that crate.
- `--skip-clean`: avoids recompiling all workspace deps every invocation
  (~3-5 min savings on subsequent runs at the cost of one larger first
  run).
- `--exclude shape-ext-python --exclude shape-ext-typescript`: matches the
  `just test-fast` / `just test` exclusion shape (the pyo3 + deno_core
  extension crates need their respective runtime envs to test fully and
  are not part of the per-feature coverage target).
- `--timeout 240`: per-test timeout. The default 60s is too short for some
  shape-vm integration tests under tarpaulin's instrumented build.

### Branch coverage

```bash
cargo tarpaulin --workspace --branch --lib --tests --skip-clean \
  --exclude shape-ext-python --exclude shape-ext-typescript \
  --timeout 240
```

Adds `--branch` which records per-branch arm hits in addition to per-line.
Critical for the strict-typing dispatch tables in `shape-vm` (the 4-table
HeapKind lockstep + Q8 / Q10 dispatch arms) where line coverage alone can
mis-report 100% on a dispatch site whose `_ => unreachable!()` arm is
never exercised.

### Dead-code measurement

```bash
cargo tarpaulin --workspace --lib --bins --tests --skip-clean \
  --exclude shape-ext-python --exclude shape-ext-typescript \
  --ignore-tests \
  --timeout 240
```

`--ignore-tests` excludes test code itself from the denominator. Pairs
with `--bins` (vs the line-coverage shape which is `--lib --tests` only)
to surface uncovered productive code in the `bin/shape-cli/`
+ `tools/shape-lsp/` targets. Pre-existing `#[ignore]`'d test arms in
shape-jit (~23 tests) + shape-cli simulation (4 tests) per CLAUDE.md
"Known Constraints" become visible-as-uncovered under this shape.

### Per-crate (incremental)

```bash
cargo tarpaulin -p <crate> --lib --tests --skip-clean \
  --include-files "<crate-dir>/*" \
  --timeout 240
```

Per-flag reasoning:

- `-p <crate>` alone is INSUFFICIENT (tarpaulin walks workspace files even
  when a single package is selected — empirical: `cargo tarpaulin -p
  shape-macros` reports 0.00% across 17,043 lines because it counts files
  it doesn't run tests for). `--include-files "<crate-dir>/*"` is the
  workaround that scopes the denominator to the target crate's files.
- Pair with `--include-files` (wildcards via `*`) to keep the
  numerator/denominator scoped consistently.

### Deep-tests feature compatibility (empirical)

Tarpaulin honors `--features` per cargo. The `just test` deep-feature
matrix maps cleanly:

```bash
cargo tarpaulin --workspace --lib --tests --skip-clean \
  --features shape-vm/deep-tests \
  --features shape-runtime/deep-tests \
  --features shape-ast/deep-tests \
  --features shape-jit/deep-tests \
  --timeout 300 \
  --exclude shape-ext-python --exclude shape-ext-typescript
```

The `--features shape-jit/deep-tests` enables the 5 modules gated behind
`deep-tests` per CLAUDE.md "Known Constraints" (`mir_compiler::integration_tests`,
`v2_array_tests`, `compiler::a1d2_tests`, `a1e_tests`); reproducibility
under tarpaulin needs `--test-threads=1` to avoid the SIGILL stdlib
JIT-cache race noted in CLAUDE.md. Add `-- --test-threads=1` to the
tarpaulin args end (tarpaulin forwards args after `--` to the test
binary).

### Benches exclusion (consistent with `just check-clean` canonical shape)

`--all-targets` minus `--benches` is the workspace gate shape per justfile
`check-clean`. Tarpaulin invocations above use `--lib --tests` (line +
branch) and `--lib --bins --tests` (dead-code) — never `--benches` —
matching the canonical-gate shape and avoiding the deleted-shape bench
files `crates/shape-vm/benches/vm_benchmarks.rs` +
`crates/shape-vm/benches/typed_access_bench.rs`.

## §6 Coverage gate threshold design

### Gate shape

- **Per-commit gate:** FOCUSED on the change — sub-agent determines scope
  per change (e.g. a fix to `crates/shape-jit/src/mir_compiler/rvalues.rs`
  runs `cargo test -p shape-jit --lib`, NOT workspace-wide tarpaulin).
  Per Phase 4 binding (Reading 2 §Test execution policy). Coverage tool
  does NOT run per-commit.
- **Phase-4b-batch-merge gate:** FULL workspace tarpaulin invocation per
  §2 (line + branch). Threshold: ≥99% per-feature OR cite a per-feature
  exception against the format below. CI fails on regression vs prior
  measured baseline.
- **Nightly gate:** Same as Phase-4b-batch-merge plus dead-code
  measurement + `--features deep-tests` matrix run. CI emits trend report;
  fails on hard regression (>2pp drop or new sub-99% feature without
  exception cite).

### Per-feature exception cite shape (binding format)

Every exception that drops a feature below the 99% line MUST cite:

1. **Feature ID** (W-series sub-cluster identifier, e.g. `W2.8 semantic
   tokens`).
2. **file:line span** of the uncovered productive code.
3. **Why hard to test** — concrete reason from: (a) requires LSP client
   protocol harness; (b) requires Python/TS extension runtime env; (c)
   requires actual GPU / Vulkan / wgpu device; (d) requires async runtime
   under specific timing; (e) requires malformed bytecode injection
   surface that isn't safely test-instrumentable; (f) requires
   distributed wire transport active QUIC connection; (g) proc-macro
   expansion not measurable by tarpaulin; (h) other (cite specific
   technical blocker).
4. **Workaround-coverage if any** — integration-test harness location,
   smoke fixture, manual verification cadence, or "none" with rationale.

Example exception:

```
- Feature: W2.8 semantic tokens
- Uncovered: tools/shape-lsp/src/semantic_tokens.rs lines 1-848
- Why hard to test: (a) requires LSP client protocol harness; tarpaulin's
  --lib measurement doesn't reach LSP request/response cycle code
- Workaround-coverage: integration test at
  tools/shape-test/tests/lsp/semantic_tokens.rs exercises the productive
  code via real LSP request/response, but does not register in tarpaulin
  per-line measurement against the shape-lsp crate
- Phase-4b disposition: W14.2-B1 to restructure LSP test harness so
  integration exercise reaches tarpaulin --lib measurement (per §4 W2.x
  recommendation (b))
```

### "Own all code quality" binding per CLAUDE.md

The exception list is NOT a graveyard — each entry must have a tracked
disposition (resolution sub-cluster ID OR v0.4 follow-up name OR
permanent-DOCUMENTED reason). Phase 4 audit-day discipline forbids
adding "tracked as follow-up to ignore" framing; every exception either
resolves in W14.2 OR cites a structural blocker with file:line.
