## (1) UAF-probe — live promoted return-ref reads the REAL value (5), VM + JIT, 100k iters

Probe `fn make() -> &int { let x = 5; return &x }`:

- Canonical value-position reads (`print(make())` / `make() + 1` / `make() == 5`):
  VM → `5 / 6 / true`; JIT → identical via an explicit `[jit-fallback]` whole-
  program deopt to the interpreter (the JIT has NO `PromotedCell` deref lowering
  and SURFACES rather than reading the raw reference pointer — VM == JIT
  semantics preserved by the deopt, not by a JIT carrier).
- 100k-iter stress `acc = acc + make()` over `0..100000`:
  - VM:  `ec=0 last=500000`
  - JIT: `ec=0 last=500000`
  (5 × 100000; the owning `Arc<SharedCell>` share keeps each promoted referent
  alive past frame-pop across 100k promotions — no UAF, no garbage, no stack-
  pointer read.)
- `soundness_guards::uaf_probe_typed_return_ref_reads_live_promoted_cell` +
  `gapa_typed_return_ref_derefs_in_value_positions` — both GREEN (assert the
  VALUE `5`/`6`/`true`, not just `run_ok`).

Note (auto-deref boundary, NOT a soundness gap): auto-deref fires at the
call-site value position (`make() + 1`), not through a re-bound `let r = make()`
consumed in a later arithmetic position (`r + 0` → infers `unknown`). That
broader binding-site deref is part of the settled v0.3.4 surface, not a
v0.3.3 floor requirement. Auto-deref is reading-THROUGH-a-reference
(fundamental ref semantics), NOT a numeric coercion — `int != number` intact
(numeric 104/0 below).
