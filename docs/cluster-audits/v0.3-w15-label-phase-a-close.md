## §0 Scope

Phase A delivers the infrastructure to label book snippets `runnable=true` vs
`runnable=false` per `v0.3-w15-book-truth-reaudit.md` §2 resolution (b) + §8.6
convention. Phase A does NOT migrate the full 691-fence book corpus — that
work is partitioned to Phase B (migration) + Phase C (CI gate wire) below.

The convention is the load-bearing precondition for the Phase 4 acceptance
criterion (`every labeled-runnable snippet runs cleanly VM == JIT;
book-truth-gate CI`).

## §1 Convention (binding)

Fence-info-string on ` ```shape ` blocks:

| Fence | Semantics | CI gate behavior |
|---|---|---|
| ` ```shape ` | runnable (default) | execute under both `--mode vm` + `--mode jit`; pass = byte-exact VM == JIT stdout |
| ` ```shape runnable=true ` | runnable (explicit) | same as default |
| ` ```shape runnable=false ` | non-runnable (pseudo-code, syntax illustration, type-system schema, intentional borrow-error shape, etc.) | skip execution; render only |

**Refused on sight:** making the default `runnable=false`. The acceptance
criterion presumes every snippet is considered runnable unless explicitly
opted out. Inverting the default would silently exempt the entire 691-fence
corpus from the CI gate at the moment of introduction — a permanent regression
in the W15-load-bearing direction.

Reserved for Phase C (NOT in scope for Phase A or Phase B):

| Fence | Phase C semantics |
|---|---|
| ` ```shape runnable=deferred cite=<cite-id> ` | DEFERRED-WITH-CITE; skip execution; `<cite-id>` must reference an open close-summary §5.X entry OR tracked follow-up sub-cluster (per re-audit §4.2) |
| ` ```shape expected="<output>" ` | strict-output gate; in addition to VM == JIT, BOTH must equal `<output>` (escape sequences supported) |

The Phase A plugin parses the `runnable=` token only. The `expected=` and
`runnable=deferred` extensions are Phase-C grammar additions to the same
plugin (one-line regex extension each; no architectural change).

## §2 Phase A deliverables (shipped)

### §2.1 Remark plugin

**Path:** `shape-web/book/book-site/src/lib/remark-shape-snippet-label.ts`
(~50 LoC including docs comment; ~20 LoC of executable parser logic).

Parses the `runnable=true|false` token from the mdast `Code` node's `meta`
field (the fence-info-string after the language ident). Propagates two
attributes:

- `node.data.shapeRunnable` (boolean) — the canonical mdast-side flag the
  Phase C book-truth-gate snippet extractor will consume.
- `node.data.hProperties['data-shape-runnable']` ("true"/"false") —
  secondary HTML attribute affordance (note: Starlight's ExpressiveCode
  renderer currently strips `hProperties` on the rendered `<pre>` wrapper;
  the canonical Phase C consumer is mdast-level, not HTML-level — see §3.3).

The `runnable=...` token is stripped from `meta` before downstream
processing so Astro/Shiki/ExpressiveCode do not misinterpret it as a
highlight directive.

Pattern: `/(?:^|\s)runnable=(true|false)(?=\s|$)/` — anchored to word
boundaries so future flags (`expected=...`, `cite=...`) parse independently.

## §3 Phase B handoff — full 691-fence migration

### §3.1 Scope

Migrate the remaining 681 ` ```shape ` fences across the book corpus to
explicit `runnable=true|false` labels. (After Phase A: 691 - 10 = 681
remaining. Strictly, the default-runnable convention means leaving a fence
unlabeled is equivalent to `runnable=true`; Phase B's value is making the
intent explicit + identifying every fence that should be `runnable=false`
before the Phase C CI gate goes live.)

### §3.2 Source-of-truth

`docs/cluster-audits/v0.3-w15-book-truth-reaudit.md` §3.2 already catalogues
the 52 byte-divergent snippets at HEAD (37 tool-divergence + 15 real
FIX-LANGUAGE). The 443 BOTH-compile-fail snippets in §3.1 (table A) are the
primary `runnable=false` candidates — most are stdlib-API declarations,
phantom-grammar illustrations, or pseudo-code that the re-audit classifies as
NON-RUNNABLE-PSEUDO (§3.0 disposition code).

### §3.3 Recommended Phase B partition

By page-territory non-overlap (5-7 pages per sub-wave per Phase 4b cadence):

| Phase-B sub-wave | Territory | Est. fence count |
|---|---|---|
| Phase-B-1 | `fundamentals/*.mdx` (20 pages) | ~200 fences |
| Phase-B-2 | `stdlib/native/*.mdx` (16 pages) | ~150 fences |
| Phase-B-3 | `stdlib/core/*.mdx` + `stdlib/domain/*.mdx` (~20 pages) | ~150 fences |
| Phase-B-4 | `advanced/*.mdx` + `tooling/*.mdx` (~25 pages) | ~140 fences |
| Phase-B-5 | `getting-started/*.mdx` + `examples/*.mdx` + `appendix/*.mdx` + `index.mdx` (~12 pages) | ~40 fences |

Total: ~680 fences across 5 parallel-dispatchable sub-waves.

### §3.4 Phase B per-fence decision rule

For each unlabeled ` ```shape ` fence at the start of Phase B:

1. Run `shape run --mode vm <fence>` + `shape run --mode jit <fence>`.
2. If both compile clean (exit 0) → label `runnable=true`.
3. If either fails to compile AND the page-content context indicates the fence
   is pseudo-code / schema illustration / intentional error shape → label
   `runnable=false`.
4. If either fails to compile BUT the page-content context indicates the fence
   should be runnable → file a FIX-BOOK-CONTENT or FIX-LANGUAGE entry per the
   re-audit §5 / §6 classification; do NOT label `runnable=false` as a
   silent skip (this would inverted-default the entire class of bugs).
5. If the fence references identifiers the page does not define (e.g. `let r
   = correlation(prices, volumes)` where `prices` is never bound) AND the
   page is documenting an API signature, not a full example → label
   `runnable=false`.

The Phase A 10-fence smoke set was chosen to exercise rules 2, 3, and 5
(plus the inverse — runnable cases that compile clean).

## §4 Phase C handoff — book-truth-gate CI wire

### §4.1 Scope

Wire the labeled corpus into CI per `v0.3-w15-book-truth-reaudit.md` §8
spec. Per-snippet harness shape at §8.1; partition by slice at §8.3; runtime
budget at §8.5; failure-mode taxonomy at §8.7.

### §4.2 Snippet extractor

A Node/TS script (~50 LoC) walks every `.mdx` under
`book-site/src/content/docs/`, parses the mdast via `remark-parse +
remark-shape-snippet-label`, and emits per-snippet `.shape` files plus a
per-fence manifest (snippet-id, `data.shapeRunnable`, page+line). The
manifest drives the per-mode harness:

- `data.shapeRunnable === true` → run both VM + JIT, gate on byte-exact
  stdout equality
- `data.shapeRunnable === false` → skip execution; manifest carries the
  fence for documentation purposes only

Snippet ID convention per §8.2: `<slice>__<page-slug>__<fence-position>__L<line>.shape`.

### §4.3 Extension points (Phase C)

Add to the plugin's regex set (one regex per attribute, anchored to word
boundaries — same shape as the existing `runnable=` regex):

- `runnable=deferred cite=<cite-id>` — DEFERRED-WITH-CITE; harness skips +
  CI fails if `<cite-id>` is not present in the open-cite-id registry
- `expected="<escaped-string>"` — strict-output gate; harness compares
  BOTH VM and JIT stdout against the expected string

Both extensions are pure plugin-level grammar additions; no Astro
integration change needed.
