Date: 2026-06-26
Branch: `strict-flip-w1-strict-provenance`

This slice removes the strict-provenance expected failure previously pinned at
`crates/shape-vm/src/executor/result_option_carrier.rs:229`.

## Landed Scope

- Added a Miri-only provenance lane for the two raw-pointer carriers exercised
  by `result_option_carrier`: `String` and `Ptr(HeapKind::TypedObject)`.
- Normal builds keep the existing `ValueSlot(u64)` / `KindedSlot { slot, kind }`
  ABI. The sidecar is behind `cfg(miri)` and does not add a runtime type
  discriminator.
- `KindedSlot::from_string_arc` and `KindedSlot::from_typed_object_raw` preserve
  the original pointer for Miri strict-provenance reads, clones, and drops.
- `TypedObjectStorage` stores a Miri-only per-field provenance sidecar so
  schema-backed `__Option` / `__Result` payload fields can be cloned and dropped
  without integer-to-pointer reconstruction.
- `result_option_carrier` now reads typed-object carriers through
  `KindedSlot::as_typed_object_storage()` and clones payloads through
  `TypedObjectStorage::clone_field_kinded()`.
- `scripts/check-miri-provenance.sh` now requires the strict-provenance
  `shape-vm --lib result_option_carrier` probe to pass; there is no expected
  failure clause.

## Remaining Blocker

This is not the full runtime representation change. The VM stack, module
bindings, JIT FFI shells, snapshots, and broad typed-object/property paths still
traffic primarily in raw `u64` address bits and reconstruct pointers at the
consumer. Making every strict-provenance path clean requires a first-class
provenance carrier or sidecar at those raw-bit boundaries, with a clear rule for
when provenance is preserved, cloned, serialized, or intentionally unavailable
at external ABI edges.

The hard invariant remains unchanged: runtime execution must not infer types.
Any broader sidecar must key off the already-proven `NativeKind` carried beside
the slot, never guess a kind from address bits or resurrect legacy carriers.
