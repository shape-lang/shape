# v0.3.3 Crate-Unit Failing-Test Classification

Synthesis of per-cluster classification buckets for the failing **unit** tests in
`shape-vm` (218) and `shape-runtime` (7). Each failing test is assigned to exactly
one bucket:

- **real_bug** — genuine correctness defect in compiler/VM/runtime; v0.3.3 release-blocking work.
- **stale_fixture** — production behavior is correct; the test's expected value / API usage predates a deliberate contract change (fix = update fixture).
- **deep_gated** — feature intentionally not built at HEAD (SURFACE-and-stop / downstream sub-cluster not landed) OR cargo-feature/SIGILL-parallelism gating; not a correctness defect.
- **pre_existing** — documented known-residual deferred work (phase-2c host-tier stubs etc.); not v0.3.3-introduced, not a wrong-result defect.

## The one real correctness defect (v0.3.3 work)

All 7 real bugs are a single root in `shape-runtime`:
`crates/shape-ast/src/parser/types.rs:1193-1205` (`parse_trait_member_signature`)
iterates the inner pairs matching only `Rule::type_param_list` and
`Rule::type_annotation`, with a `_ => {}` catch-all swallowing the
`Rule::function_params` pair that the grammar (`shape.pest:187`:
`"async"? ~ ("method"|"fn") ~ ident ~ "?"? ~ type_params? ~ "(" ~ function_params? ~ ")" ~ ...`)
actually emits. Every trait method therefore parses with arity 0, producing
`TraitImplArityMismatch{expected:0, got:N}`. The impl-side `method_def` parser
(`functions.rs:156-162`) handles `function_params` correctly (so `got:N` is right) —
the asymmetry confirms the trait-side defect. Predates HEAD (af0ffb41,
never updated after grammar surgery cd7d97a4); NOT in CLAUDE.md Known Constraints
and NOT in the documented shape-test residual clusters. Fix = add a
`Rule::function_params` arm calling `parse_function_param` over the param children.
