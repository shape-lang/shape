## Executive summary (read first)

The unit-test signal (22 failing / 14 baseline = +8) **understates the user-
facing state significantly**. The empirical real-LSP exercise in §D
surfaces **at minimum these high-impact regressions on standard editor flows**
that no unit test covers:

1. **`textDocument/completion` after `xs.` returns zero items** for both
   stdlib-typed arrays AND user-method dispatch on user-defined types — the
   #1 keystroke-frequency completion path is dead in a real editor.
2. **`textDocument/signatureHelp` returns null** for both stdlib calls
   (`distance(`) and user-method calls (`u.hello(`) mid-typing — the call-site
   parameter-hint path is dead.
3. **`textDocument/documentSymbol` misses `trait` / `type` / `impl` / `enum`**
   on every file with them — only `Item::Function` / `Item::VariableDecl` /
   `Item::TypeAlias` / `Item::Enum` / `Item::ForeignFunction` are recognized
   in the dispatch (`document_symbols.rs:47-126`). The outline view in any
   editor shows nothing for the substantive items of a trait-heavy file.
   Compounding: ranges fall back to `idx as line` (`line as u32` at
   `document_symbols.rs:151`) — the loop's enumerate index is passed as a file
   line number, so even the items that ARE returned point at the wrong
   position.
4. **Inferred reference-mode hints are silently absent** in inlay hints,
   hover signatures, and signature-help across the board (`: &string` /
   `: &mut string` never rendered). The 5 reference-mode test failures in §B
   are surface symptoms of this regression; the empirical run in §D confirms
   the renderer path is also dead end-to-end.
5. **Inlay-hint type inference loses propagation** through fn-call chains —
   `let d = distance(p: Point, q: Point) -> number` shows `: any` instead of
   `: number`; method-chain receivers degrade to `: Array` (no element type).
6. **`textDocument/codeAction` returns 0 actions** even when invoked with a
   reachable diagnostic (the `Undefined variable` case in `broken.shape` —
   diagnostic code is `SEMANTIC`, no quickfix triggers).
7. **`textDocument/prepareCallHierarchy` returns `[]`** even on a function
   that IS visible to `documentSymbol`; the entire call-hierarchy chain is
   dead in editor.
8. **Annotation hover** (`@description`, `@trace`, etc.) returns null in real
   editor flow despite the test fixture path claiming coverage.
9. **Hover-rendered method signatures use the DELETED `name(args): RetType`
   Form A syntax** (7 sites in `hover.rs` + 1 in `type_inference.rs`, see §B
   row "test_hover_impl_trait_resolves_members_from_module_context"). Commit
   `cd7d97a4` (2026-05-18) "Grammar surgery + 70-file migration: delete
   Form A trait method colon-return syntax" deleted the syntax from the
   parser; the LSP still emits it as rendered output.
10. **Find-references cross-file IS now plumbed** (`references` handler
    `server.rs:1239-1286` uses `get_references_cross_file`), defying the 2026-
    05-17 audit's claim. PARTIAL → COVERED. (Confirmed in harness §D: empty
    result from a same-file-only fixture, but the code path goes through the
    workspace iterator.)

The good news: the protocol surface (initialize-capabilities) has matured
substantially since the 2026-05-17 audit (`v0.3-lsp-feature-spec.md`). Many
W2.x waves landed — typeDefinition / implementation / declaration /
documentHighlight / executeCommand / fileOperations.willRename / pull
diagnostics / inlay-hint resolve / semantic-tokens range+delta / code-lens
trait-implementation + reference-count / cross-file references + rename are
all registered as providers, and the eager workspace symbol scan works.

The bad news is item 1–10 above: substantial **handler-side regressions**
have accumulated since (likely R8 W-series type-system tightening
side-effects, plus the cd7d97a4 Form-A trait-syntax deletion that broke 7
test fixtures + 8 LSP render sites). The user 2026-05-25 directive's bar is
"inline hints top notch + en-par or better than rust-analyzer." We are
substantively below that bar on items 1, 2, 4, 5, 8 in particular. **5–10
sessions is the right honest sizing.**

Sub-cluster partition in §E. Per-test routing in §G.

### F.2 User-decision items (explicit asks for supervisor + user ratify)

1. **Test matrix for empirical re-verify.** VS Code only, OR VS Code +
   neovim, OR VS Code + neovim + Helix + Zed? Today only VS Code ships an
   adapter (`editors/vscode/`). nvim wiring via `vim.lsp.start` works (per
   §D) but no contributed snippet exists. Recommendation: **VS Code + neovim
   minimum** — neovim's lightweight LSP attachment provides protocol-
   correctness coverage that VS Code's heavier client masks; covers both the
   "popular IDE" and the "minimalist editor" populations. Helix + Zed are
   marginal additional value vs the integration cost. **Decision needed
   before LSP-L dispatch.**

2. **BindingStorageClass inlay hints (Q25.C.7-class).** v0.3-gating or v0.4?
   ADR-006 §2 named the storage-class lattice (Direct / UniqueHeap /
   SharedCow / SharedAtomic / SharedAtomicMut); surfacing it as inlay hints
   would be a strong "top notch" signal for the user 2026-05-25 directive,
   but it's a multi-session piece that adds risk to v0.3 close. Recommendation:
   **v0.3-polish** (in scope if remaining LSP-B/C/D close cheaply; otherwise
   ship type-prop + chain hints alone for v0.3 and defer storage-class to
   v0.4). **Decision needed during LSP-H dispatch.**

3. **Formatter depth (LSP-M).** v0.3-gating or v0.3-polish? The shallow
   token-level formatter doesn't fix internal operator spacing or extra-
   space-in-params (`fn main(  )` passes through). Per the `formatting.rs:5`
   docstring's "code can never be destroyed" invariant, deepening to a real
   AST-rewrite formatter is a multi-session piece. r-a's `rustfmt` integration
   is the parity reference. Recommendation: **v0.3-polish** — current shallow
   formatter is "non-destructive correct," not "wrong." Defer depth to v0.4
   unless user pushes back. **Decision needed before LSP-M dispatch.**

4. **Refactor-family assists (extract-fn / inline / convert-* family).**
   r-a has ~100 assists; Shape has ~10. The user "en-par" bar is interpretive.
   Recommendation: **v0.4** for the convert-* family (>50 assists, multi-week
   territory); **v0.3-polish** for extract-fn / extract-var (already partially
   present). **Decision needed in §E close.**

5. **Magic completions (`.if`, `.match`, postfix family).** r-a documents this
   as a polish-tier signature feature. Recommendation: **v0.3-polish** if
   LSP-C method-completion has slack capacity; otherwise **v0.4**.
