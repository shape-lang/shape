## §2 Labeling convention — how does the book mark runnable vs non-runnable?

### Finding: NO formal runnable/non-runnable convention exists in the book at HEAD.

Empirical evidence (grep at HEAD `e6b14a90` over `book-site/src/content/docs/`):

- Zero `\`\`\`shape\s+\w+` fence-info-string variants. Every shape block uses bare `\`\`\`shape`.
- Zero usages of `<ShapeSnippet>` Astro component in `.mdx` files (component definition exists at `/home/dev/dev/shape-lang/shape-web/book/book-site/src/components/ShapeSnippet.astro` and accepts a `runnable={true|false}` prop defaulting to `false`, but the component is never imported or invoked in any `.mdx`).
- Zero usages of `<ShapePlayground>` Astro component (same shape; default `runnable=true`).
- Per-page frontmatter does NOT carry a runnable flag (frontmatter is `title`/`sidebar.order`/`llm_weight` only).

The legacy snippet pattern at `/home/dev/dev/shape-lang/shape-web/book/snippets/` (8 `.shape` + 8 `.expected` pairs, totaling 16 files; harness at `/home/dev/dev/shape-lang/shape-web/book/test-snippets.sh`) is a separate scaffold predating the Astro Starlight book and is unused by any current `.mdx` page (the snippets are at `snippets/fundamentals/` and `snippets/getting-started/` and are exercised only by the standalone harness).

### Surface-and-stop per Reading 3 cadence

The Phase 4 acceptance criterion text ("every labeled-runnable snippet runs cleanly VM == JIT") presumes a label distinguishing runnable from non-runnable. **No such label exists in the book at HEAD.** Three resolutions are possible; this audit surfaces the choice without acting:

- **Resolution (a) — every `\`\`\`shape` fence is de-facto labeled-runnable.** This is the operational default this audit's §3 matrix assumes (treats all 691 fences as labeled-runnable). Under this reading the acceptance criterion is the most strict.
- **Resolution (b) — adopt a fence-info-string convention** (e.g. `\`\`\`shape runnable=false` for snippets that document syntax-error shapes, borrow-error shapes, language-reference grammar fragments, type-system illustrations, pseudo-code). Requires either (i) a Starlight remark plugin that filters by fence info OR (ii) a per-snippet pre-processor that strips the flag before rendering. W15.3 book-truth-gate CI would need to honor this flag.
- **Resolution (c) — adopt per-page frontmatter `runnable_snippets: false` field** for whole-page exclusions (e.g. `advanced/ownership-deep-dive.mdx` documents borrow-error shapes; the page-level fix is to mark the page non-runnable rather than per-fence).

Recommended: (b) at fence-info-string level with a small remark plugin (≤20 LoC); coarser-grained than (c) but allows pages to mix runnable + non-runnable fences (e.g. `fundamentals/error-handling.mdx` has both runnable examples and AnyError-schema pseudo-code). This recommendation is for supervisor / strategic-owner ratification before W15.2-N closure-wave kicks off.

**Refused on sight (#10 anti-deferral):** "defer the labeling-convention decision to v0.4". The W15 acceptance criterion text REQUIRES a labeling convention to be operational; deferring the convention defers the criterion. Surface-and-stop until supervisor rules.

### §3.0 Methodology + columns

Every `\`\`\`shape` fence executed under both `--mode vm` and `--mode jit` via the release binary at `/home/dev/dev/shape-lang/shape/target/release/shape`, with:

```
out=$(timeout 15 ./target/release/shape run --mode $mode <snippet> 2>/dev/null | tr '\n' '|' | tail -c 300)
```

stdout captured to `/tmp/w15-audit/results.tsv` (1382 rows = 691 snippets × 2 modes). A second pass captured exit codes via stdout-discarded invocation to `/tmp/w15-audit/exit_codes.tsv` for compile-error classification.

**Column legend:**

- **VM == JIT?** = byte-equality of the stdout-tail-300 capture (after newline → `|` substitution).
- **Disposition codes** (per dispatch §3 spec):
  - **CLEAN** — VM == JIT AND output matches book-documented expected (where book documents an expected output).
  - **FIX-BOOK-CONTENT** — VM == JIT AND output mismatches book-documented expected, OR book expects a non-trivial output but snippet produces empty/`{...}` JSON-default rendering. Sub-disposition: book content needs editing (output line update; syntax fix; API alignment).
  - **FIX-LANGUAGE** — actual VM vs JIT divergence (semantic bug; the snippet is intended-correct + the language has a bug).
  - **DEFERRED-WITH-CITE** — snippet blocked on V3-S5 ckpt-5/ckpt-6 STRICT close territory (op_new_array(0) SURFACE) OR W17-marshal-return-arms OR similar named-and-tracked language-side residual; book carries a SURFACE callout (or should after W15.2-N) per the W3.2-C / W3.2-D precedent.
  - **NON-RUNNABLE-PSEUDO** — snippet is grammar-reference / pseudo-code / schema-illustration NOT intended to be run (e.g. `advanced/ownership-deep-dive.mdx` borrow-error illustrations, `fundamentals/error-handling.mdx` AnyError schema). Fails to compile by design. Should be marked non-runnable per §2 resolution (b).

## §8 Book-truth-gate CI integration shape

W15.3 book-truth-gate enforces "every labeled-runnable snippet runs cleanly VM == JIT" at CI on every shape-web book commit (and on shape/ commits that change stdlib / runtime / grammar that the book depends on).

### §8.1 Per-snippet harness shape

```bash
# Per snippet:
out_vm=$(timeout 15 $SHAPE run --mode vm $snippet 2>/dev/null)
ec_vm=$?
out_jit=$(timeout 15 $SHAPE run --mode jit $snippet 2>/dev/null)
ec_jit=$?

# Pass conditions:
# - ec_vm == 0 && ec_jit == 0
# - out_vm == out_jit (byte-exact match)
# - if expected_output declared via fence-info-string "expected=..." OR .expected file: out_vm == expected
```

### §8.2 Snippet extraction

Reuse the `/tmp/w15-audit/extract.py` pattern. Walk every `.mdx` under `book-site/src/content/docs/` + extract every `\`\`\`shape` fence + emit per-snippet `.shape` file under a build-step tempdir.

Snippet ID convention: `<slice>__<page-slug>__<fence-position-in-page-zero-indexed>__L<fence-open-line-number>.shape`.

### §8.3 Per-slice partition for parallel CI execution

Per-snippet wall-time ~3s (1s startup + 1s VM + 1s JIT). 691 snippets / 8 parallel jobs ≈ 4-5 min for the full corpus.

| Slice | Snippet count | Estimated CI runtime (8-way parallel) |
|---|---:|---|
| A | 215 | ~80s |
| B | 328 | ~120s |
| C | 27 | ~10s |
| D | 62 | ~25s |
| E | 59 | ~25s |
| **TOTAL** | **691** | **~260s = 4-5 min** |

Per CI: one job per slice (parallel) OR one job per page (more parallelism). Per-page parallelism yields ~10s per page max.

### §8.4 Persistence shape

Per-snippet results persisted as artifact (TSV: snippet-id + mode + ec + stdout-hash + expected-hash + status). On regression: diff vs last-known-green; emit per-snippet diff block in CI log.

### §8.5 Runtime budget

Per-slice budget: 5 min per slice (per-page parallel). Total full-corpus: 8 min including snippet extraction + binary build + harness setup. Fits comfortably in standard CI runner time-budget.

### §8.6 Fence-info-string convention (recommended)

Per §2 resolution (b), the recommended fence-info-string convention:

- `\`\`\`shape` (default) → labeled-runnable; gate executes VM AND JIT; pass-condition is VM == JIT
- `\`\`\`shape runnable=false` → labeled-non-runnable; gate skips execution; the fence is rendered but not gated
- `\`\`\`shape runnable=deferred cite=<cite-id>` → DEFERRED-WITH-CITE; gate skips execution; cite-id must reference an open close-summary §5.X entry OR a tracked follow-up sub-cluster
- `\`\`\`shape expected="<output>"` → strict-output gate; in addition to VM == JIT, BOTH must equal `<output>` (escape sequences supported)

Implementation: ~20-30 LoC remark plugin + extractor pre-pass; out-of-scope for this audit.

### §8.7 Failure-mode taxonomy at CI

- VM exit ≠ 0 → snippet doesn't compile / runtime error → FAIL (cite snippet path + line)
- JIT exit ≠ 0 → JIT compile fail → FAIL (cite snippet path + line; if W12 fall-through emits, log the diagnostic)
- VM stdout != JIT stdout → divergence → FAIL (cite both stdout-tails)
- expected declared + VM stdout != expected → FAIL (cite expected + actual)
