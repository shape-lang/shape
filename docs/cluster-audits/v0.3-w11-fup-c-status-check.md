## §3. `W11-followup-jit-spread-expand` bound verification

Close doc §4 + close-summary §5.1 entry 10 documented the surfaced JIT spread codegen bug at `crates/shape-vm/src/mir/lowering/expr.rs:237-247`.

Grep-verified at HEAD `crates/shape-vm/src/mir/lowering/expr.rs:237-247`:

```rust
fn lower_array_expr(builder: &mut MirBuilder, elements: &[Expr], temp: SlotId, span: Span) {
    let operands: Vec<_> = elements
        .iter()
        .map(|expr| lower_expr_as_moved_operand(builder, expr))
        .collect();
    builder.push_stmt(
        StatementKind::Assign(Place::Local(temp), Rvalue::Aggregate(operands.clone())),
        span,
    );
    emit_container_store_if_needed(builder, ContainerStoreKind::Array, temp, operands, span);
}
```

Bug shape confirmed at HEAD: `lower_array_expr` lowers each element (including spread `...a`) as a single moved operand via `lower_expr_as_moved_operand`, producing a flat `Aggregate([..., Move(temp_a), ...])` regardless of whether the source `temp_a` is itself an array. No `Spread` Rvalue variant exists; no per-element expansion at codegen time.
