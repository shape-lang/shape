## §0 Minimal repro

```shape
enum Snapshot { Hash(string); Resumed; }

fn snapshot() -> Snapshot {
    Snapshot::Hash("abc123")
}

fn main() {
    match snapshot() {
        Snapshot::Hash(id) => print("id = " + id),
        Snapshot::Resumed => print("resumed"),
    }
}
```

Expected: prints `id = abc123` on both VM and JIT. `id` should infer to
`string` from the variant payload type in the enum definition.

## §1 Empirical results VM + JIT (HEAD 79783499)

| Tier | last-line | ec | Shape |
|---|---|---|---|
| `--mode vm` | `Cannot infer types for binary operation Add: operand types are string and unknown` | 1 | **Compile-time semantic error** (no execution path entered) |
| `--mode jit` | (same compile error surfaced during bytecode compilation) | 1 | **Compile-time semantic error** (same gate) |

**Workaround verified working both tiers:**
```shape
Snapshot::Hash(id: string) => print("id = " + id),
```
→ both tiers ec=0, last-line `id = abc123`.

## §2 Classification per no-known-incorrectness binding

- **NOT** memory-unsafety / SEGFAULT.
- **NOT** VM/JIT divergence (both tiers gate identically at compile).
- **NOT** silent-wrong-output (no execution path entered).
- **NOT** runtime crash / panic.
- **MAYBE** spurious-reject of valid code — depends on whether the
  language spec mandates that enum-pattern tuple-payload binders carry
  the variant's payload type without annotation.

The language reference at `book-site/.../enums.mdx` describes
`Variant(binding)` as carrying the payload's declared type. By that doc-
contract the rejection IS spurious. Two readings:

- **Strict reading** (spec-driven): doc says it works → known-incorrect
  → v0.3-gating spurious-reject.
- **Pragmatic reading** (clean-error, workaround exists, no execution
  bug): incomplete-but-CLEAN with explicit-annotation workaround.

**Routing recommendation:** **v0.4** — the failure mode is a CLEAN
compile error with a documented workaround. The fix is bounded (Pattern
binding lookup against `EnumDef`; 4-5h scope; low risk). Per the user's
"incomplete-but-CLEAN → v0.4-OK" leg of the binding this is the right
shape. **However**: if the supervisor reads the doc-contract leg as
stronger, this flips to v0.3-gating.

### Fix recipe (if supervisor flips to v0.3-gating)

**File:** `crates/shape-runtime/src/type_system/inference/expressions.rs`
**Function:** `bind_pattern_vars_typed` (~lines 1342-1426).
**Buggy site:** lines 1394-1397 — `PatternConstructorFields::Tuple(patterns)`
arm passes `None` as the field type into the recursive
`bind_pattern_vars_typed(p, None)` call, producing un-constrained
fresh type variables.

**Fix shape:**

1. Extract `enum_name` from `Pattern::Constructor { enum_name, variant, fields }`.
2. Look up `EnumDef` via `self.env.get_enum(enum_name)`.
3. Find the matching `EnumVariant { name, payload }`.
4. Extract per-field types from the variant's payload.
5. Thread each resolved type into the recursive
   `bind_pattern_vars_typed(p, Some(field_ty))` call.

**Estimated effort:** 4-5 hours. Low risk (fills a documented gap; no
core inference refactor; no opcode emission changes).
