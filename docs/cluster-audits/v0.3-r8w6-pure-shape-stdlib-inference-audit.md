## §2 — Root-Cause Clustering

### Cluster A: Module-Level Binding Rejection (2 files)
- `core/log.shape` — `let mut current_level = 1` at module level
- `core/distributions_advanced.shape` — `let PI = 3.14...` at module level

**Root cause:** Shape v0.3 does not support module-level `let` or `let mut` bindings (const-only per compiler rule). The files contain documentation-mandated module-scope constants (log levels, mathematical constants) that violate the current language semantics.

**Disposition:** v0.3-gating. Requires a new language feature: "module-level const bindings" or "module-level mutable state" per v0.4 design. This is NOT a bug — the code attempts an unsupported construct.

---

### Cluster B: Generic-Arithmetic Inference Loss (5 files)
- `core/utils/testing.shape` — `actual == expected` (Equal)
- `math/optimize.shape` — `sums[j] + vertices[i][j]` (Add)
- `math/linalg.shape` — `a[i] * b[i]` (Mul)
- `math/rotation.shape` — `rot * pt` (Mul)
- `math/interpolation.shape` — `nx > 1` (Greater)

**Root cause:** Function parameters declared without type annotations. Compiler cannot infer the operand types for binary operations at the call site. This is the pre-existing "stress_inference / closure inference regressions / monomorphization gaps" class mentioned in CLAUDE.md §Known Constraints.

**Example:** In `testing.shape:35`, `assert_eq(actual, expected, ...)` has no type constraint on `actual` or `expected`. When the function body attempts `actual == expected`, the compiler sees two `Type::Variable(TypeVar::fresh())` and cannot unify them with a concrete type like `Int64` or `Float64`.

**Disposition:** v0.3-gating. Spurious-reject of valid code. The function signatures CAN be fixed by adding explicit type annotations OR by improving the type-inference engine to perform bidirectional inference from call sites (not currently shipped). For v0.3 ship, recommend explicit type annotations in the stdlib.

---

### Cluster C: Empty-Array Element-Type Loss (2 files)
- `core/utils/property_testing.shape` — `let mut results = []` (line 41)
- `core/monte_carlo.shape` — `let mut results = []` (line 33)

**Root cause:** Empty array literal `[]` creates an untyped `Array<TypeVar::fresh()>`. The compiler cannot infer the element type from subsequent `.push()` calls when the argument type is itself unknown (higher-order inference loss).

**Example:** In `property_testing.shape:41-46`, the function signature is `pub fn run_properties(tests)` (no type annotation). Inside, `results = []` is created and later populated with results of `property(...)` calls. But `property(...)` also has no type annotation, so the compiler cannot propagate the element type backwards to the empty-array binding.

**Disposition:** v0.3-gating. Fixable by annotating the empty array: `let mut results: Array<...> = []`. Alternatively, ensure the first `.push()` argument has a known type.

---

### Cluster D: Closure-Return & Function-Param Inference Loss (1 file merged into B)
- Subsumed by Cluster B (the root cause is the same: unannotated function parameters).

## §3 — v0.3-Gating Cluster Dispatch Shapes + Estimates

### Dispatch A: Module-Level Binding Support (New Feature)
**Files affected:** 2
- `core/log.shape` (log levels + current_level)
- `core/distributions_advanced.shape` (mathematical constants)

**Fix shape:** Implement module-level binding syntax. Two options:
1. **Option A.1 (const-only, simpler):** Add `const PI = ...` at module level (similar to Rust). Requires parser + type-system + compiler changes. ~4-6 hours integration.
2. **Option A.2 (mutable, larger):** Add `let mut` at module level with thread-local or global state. Requires semantics design + execution model + multiple subsystem changes. ~2-3 days.

**Recommendation:** A.1 (const-only) is simpler and sufficient for these stdlib files.

**Estimated session-shape fix cost:** ~1 session (4-6 hours if following const-binding path; 2-3 days if full mutable-state).

---

```shape
pub fn run_properties(tests: Array<{ name: string, trials: int, gen: () -> _, prop: (_) -> bool }>) {
    let mut results: Array<{ passed: bool, name: string, trials: int, counterexample: _ }> = []
    var passed_count = 0
    var failed_count = 0

    for test in tests {
        let result = property(test.name, test.trials, test.gen, test.prop)
        results.push(result)
        if result.passed {
            passed_count = passed_count + 1
        } else {
            failed_count = failed_count + 1
        }
    }

    {
        passed: passed_count,
        failed: failed_count,
        total: tests.len(),
        results: results
    }
}
```
