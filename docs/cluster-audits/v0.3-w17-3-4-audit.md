## §1 FieldType at HEAD — Current Flat Enum

### §1.A Definition + Per-Variant Categorization

At `crates/shape-runtime/src/type_schema/field_types.rs:35-77`:

```rust
pub enum FieldType {
    // Primitives (scalars — NO per-container variant)
    F64,                            // float; NativeKind::Float64
    I64,                            // int; NativeKind::Int64
    Bool,                           // bool; NativeKind::Bool
    String,                         // string; NativeKind::String (Arc<String> carrier)
    Timestamp,                      // timestamp; NativeKind::Int64
    Decimal,                        // decimal; stored as f64; NativeKind::Float64
    
    // Width-specific integers (scalars)
    I8, U8, I16, U16, I32, U32, U64 // per NativeKind variants
    
    // Containers (FLAT — element type parameterized but no per-container variant)
    Array(Box<FieldType>),          // Vec<T>; points to HeapKind::TypedArray
    Object(String),                 // user-defined struct/enum/named; points to HeapKind::TypedObject
    
    // Type system
    Option(Box<FieldType>),         // Option<T> (W17.2-B); per-value kind from parallel-field_kinds track
    Any,                            // dynamic; forbidden in new code per strict-typing plan
}
```

### §1.B Categorization

| Variant | Category | Heap Target | Current Consumer Decision Burden |
|---------|----------|------------|------|
| F64, I64, Bool | Scalar | None | None; direct NativeKind projection |
| String | Scalar-heap | Arc<String> | Special-cased per ADR-005 §2 exception |
| Timestamp, Decimal | Scalar | None | Store as i64/f64; NativeKind projection direct |
| I8–U64 | Scalar-width | None | Stored as i64 in slot; width truncated on r/w |
| **Array(T)** | **Container** | **HeapKind::TypedArray** | **Element type T buried; consumers pattern-match to extract** |
| **Object(name)** | **Container** | **HeapKind::TypedObject** | **Schema name only; consumers query registry for fields** |
| **Option(T)** | **Container-like** | **NaN-boxed** | **Per-value kind from parallel-field_kinds track; T not projected** |
| Any | Fallback | Varies | Forbidden; legacy only |

### §1.C Relationship to NativeKind & HeapKind

**FieldType → NativeKind projection** (`to_native_kind()` at line 187):

- Scalars: direct 1:1 projection (F64→Float64, I64→Int64, Bool→Bool, String→String, etc.)
- Array(T): **All routes to `Ptr(HeapKind::TypedArray)`** — inner T is lost; consumers must separately track element type
- Object(name): **All routes to `Ptr(HeapKind::TypedObject)`** — schema name is lost; consumers must query registry
- Option(T): **Explicitly refuses** with `Err(AnyTypeNotStrictlyTyped)` — per-value kind lives in parallel-field_kinds track; static FieldType projection is unsound
- Any: **Refuses** — strict-typing plan forbids

**HeapKind** (`crates/shape-value/src/heap_variants.rs`):
- 17 variants (String, TypedObject, Closure, Decimal, BigInt, DataTable, Future, TaskGroup, [VACATED 8], Temporal, TableView, Content, TraitObject, Module, Annotation, FilterExpr, HashMap, ...)
- **Currently NO per-container variants** (e.g., no `HeapKind::ArrayInt64`, `HeapKind::HashMapStringInt64`)
- HashMap and Set exist at HeapKind level (dispatch targets) but NOT at FieldType level (schema descriptors)

## §3 Refinement Target Shape — Proposed Per-Container Variants

### §3.A Proposed Design

**Primary recommendation:** Extend FieldType with **per-container variants** while keeping scalars flat. Three options evaluated; Option 1 selected.

#### **Option 1 (RECOMMENDED): Flat enum with container discriminant + element wrapper**

```rust
pub enum FieldType {
    // === Scalars (flat; no per-container variant) ===
    F64, I64, Bool, String, Timestamp, Decimal,
    I8, U8, I16, U16, I32, U32, U64,
    
    // === Containers (per-container variants) ===
    /// Array<T>: generic typed vector
    /// - Element type carried inline
    /// - Heap target: HeapKind::TypedArray
    Array(Box<FieldType>),
    
    /// HashMap<K, V>: key-value map
    /// - Key type (typically String, Int64)
    /// - Value type carried inline
    /// - Heap target: HeapKind::HashMap (currently exists at HeapKind level)
    HashMap { key: Box<FieldType>, value: Box<FieldType> },
    
    /// Set<T>: unique element collection
    /// - Element type carried inline
    /// - Heap target: future HeapKind::Set (new ordinal to be assigned)
    Set(Box<FieldType>),
    
    // === Type System ===
    /// Option<T>: discriminated union with None/Some
    /// - Inner type carried inline; per-value kind from parallel-field_kinds track
    Option(Box<FieldType>),
    
    // === Legacy ===
    /// Nested object of known type (user struct/enum/named)
    /// - Name carries schema lookup key
    Object(String),
    
    /// Any/dynamic type (forbidden in new code per strict-typing plan)
    Any,
}
```

**Rationale for Option 1:**
- Minimal surface change: only extends match arms where containers appear.
- Preserves flat scalar dispatch (no new discriminant layer).
- Carrier shape mirrors existing Array/Option pattern (Box<inner>).
- HashMap struct variant allows K/V separation without nested Pair wrapper.
- Aligns with ADR-005 §1 single-discriminator principle: HeapValue::kind() remains canonical; FieldType carries schema-layer detail only.
- **No dynamic tag decode on hot paths** — per-container variants ARE the schema discriminator; NativeKind projection refuses statically for containers (mirrors Option/Any shape).

**Set implementation note:**
- Currently no HeapKind::Set exists; W17.3-4 creates it alongside FieldType::Set.
- Ordinal assignment: next available slot after the VACATED 8 (see CLAUDE.md v0.2.0 known constraints, W5 close audit).
- HeapValue gains `Set(Arc<HashSet<T>>)` variant with matching ordinal.
- Parallel-kind track handles per-element kind at runtime (matches Array/HashMap strategy).

#### **Option 2 (Rejected): Separate toplevel variant per container**

```rust
pub enum FieldType {
    // Scalars (same)
    // ...
    
    ArrayField { elem: Box<FieldType> },
    HashMapField { key: Box<FieldType>, value: Box<FieldType> },
    SetField(Box<FieldType>),
    ObjectField(String),
    OptionField(Box<FieldType>),
}
```

**Why rejected:**
- Noise: scalar consumers still pattern-match on ArrayField/HashMapField/etc., not a unifying "container" category.
- Doesn't reduce match-arm burden for the primary decision points (Pattern A–D above).
- Extra discriminant layer per container provides no semantic clarity over the inline-variant shape.

#### **Option 3 (Rejected): Trait-object carrier**

```rust
pub enum FieldType {
    // Scalars
    // ...
    
    Container(Box<dyn ContainerFieldType>),
}

pub trait ContainerFieldType: Send + Sync {
    fn element_type(&self) -> &FieldType;
    fn to_native_kind(&self) -> Result<NativeKind, FieldKindError>;
}
```

**Why rejected:**
- Violates ADR-005 §1 single-discriminator: adds a second discriminator layer (trait vtable dispatch) above the canonical HeapValue::kind() path.
- Serialization complexity: serde cannot drive trait objects directly; requires custom ser/de.
- Performance: vtable lookup on every container access (consumer sites ~85 for Array alone).
- Escape-hatch attractor: containerizes too much; consumers end up querying trait methods instead of pattern-matching.

## §8 Summary & Recommendation

### §8.A Findings

1. **"Per-container" means:** Extend FieldType with **per-container variants** (Array, HashMap, Set, Option) that carry element/key/value types inline, while leaving scalar types flat and Object/Any unchanged.

2. **Consumer decision burden:** Current flat enum forces ~728 sites to either (a) pattern-match both container variants and scalar cases separately, or (b) manually extract element types and thread them through logic. Per-container variants reduce noise and clarify container dispatch.

3. **Bounded scope:** Scalars (F64, I64, Bool, String, width ints, Timestamp, Decimal) stay flat. Containers become per-variant. Object and Any unchanged (legacy). Option continues to refuse static kind projection (parallel-field_kinds track handles per-value kind).

4. **ADR alignment:** No amendment needed. Option 1 design (struct variant for HashMap; Box wrapper for element types) operates entirely within ADR-005 §1 and ADR-006 existing rules. HeapValue::kind() remains canonical; FieldType carries schema detail only.

5. **Risk assessment:** Low–Medium overall. Partition by producer→consumer supply-chain mitigates compiler integration risk. Serialization format is stable (Serde enum discriminant). Snapshot round-trip validation guards runtime integration.
