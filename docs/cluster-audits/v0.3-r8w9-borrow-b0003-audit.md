## §3 Root Cause Analysis

### The Core Issue: Unconditional Categorical Ban

The compile-time checks at sites A (line 786) and B (line 4829) **unconditionally reject any reference binding at module scope**, regardless of whether the reference actually escapes its owner.

**Condition that fires:**
```rust
if ref_borrow.is_some()  // <- True for ANY Reference expression
```

### What Should Happen

Per comments throughout the codebase (e.g., helpers_reference.rs line 482: "Lexical reference tracking removed — MIR borrow checker is sole authority"), **the MIR borrow solver is the authority for reference lifetime validation.** The correct flow should be:

1. Compile `let r = &x` to bytecode (emits `MakeRef` + `StoreModuleBinding`)
2. MIR lowering creates a loan fact for `&x`
3. MIR borrow solver analyzes the loan's region:
   - If loan issued at binding and last used before `x` is dropped → VALID
   - If loan escapes (e.g., stored in a non-local container or returned) → emit B0003
4. Reject only if the solver determines actual escape

### Why the Ban Exists (Historical Context)

Per git commit `a2c975f1` (borrow redesign follow-up), the check was added during the borrow redesign transition. However, it appears to be a **transitional safety fence** rather than a final design. The asymmetry is revealing:

- **Local variables inside functions** (line 5040): `ref_borrow` is passed to `finish_reference_binding_from_expr` **without rejection**
- **Module-level variables** (line 786, 4829): `ref_borrow` is **unconditionally rejected**

This asymmetry suggests the ban was meant to be temporary while the MIR solver was being wired up, but was never removed.

### Key Evidence: Local Variables Work

At statements.rs line 5040-5046 (inside function scope, module-binding path):
```rust
self.finish_reference_binding_from_expr(
    binding_idx,
    false,
    name,
    value,
    ref_borrow,  // <- Passed UNCONDITIONALLY, even if Some
);
```

The same `ref_borrow` value that triggers rejection at module level is **accepted** in the function-context path and passed to tracking. This proves the infrastructure to handle reference values exists and works.

**Reason:** No `ref_borrow` is set when the Reference is used directly (not bound).


## Summary

**Symptom:** `[B0003] cannot return or store a reference that outlives its owner` at `let r = &x` binding site, while `x` is in scope.

**Root Cause:** Compile-time categorical ban on `ref_borrow.is_some()` at module scope (sites A & B), which unconditionally rejects ANY reference binding regardless of whether it actually escapes.

**Fix:** Remove the two conditional rejection blocks (sites A, lines 786–795; site B, lines 4829–4838) and let the MIR borrow solver be the authority, per documented design.

**Fix Size:** S — Single deletion, no redesign. Two blocks, ~20 lines total.

**Working Alternative (for doc if needed):** Direct use `let val = &x + 1` works today; this is equivalent for value-semantics but less idiomatic for reference-semantics patterns.

**Gating Recommendation:** If fix lands in v0.3, ownership-deep-dive.mdx §"First-Class References" examples (currently documented as working) will then work. No doc rewrite required; audit validates the documented contract was correct.
