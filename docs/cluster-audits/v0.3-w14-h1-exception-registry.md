### Binding format (verbatim from W14.1 audit §6)

Every exception that drops a feature below the 99% line MUST cite:

1. **Feature ID** (W-series sub-cluster identifier).
2. **file:line span** of the uncovered productive code.
3. **Why hard to test** — concrete reason from:
   - (a) requires LSP client protocol harness
   - (b) requires Python/TS extension runtime env
   - (c) requires actual GPU / Vulkan / wgpu device
   - (d) requires async runtime under specific timing
   - (e) requires malformed bytecode injection surface that isn't safely test-instrumentable
   - (f) requires distributed wire transport active QUIC connection
   - (g) proc-macro expansion not measurable by tarpaulin
   - (h) other (cite specific technical blocker)
4. **Workaround-coverage if any** — integration-test harness location, smoke fixture, manual verification cadence, or "none" with rationale.

The exception list is NOT a graveyard — each entry must have a tracked
disposition (resolution sub-cluster ID OR v0.4 follow-up name OR
permanent-DOCUMENTED reason).

## §3 Architectural-gap DOCUMENTED EXCEPTIONS (sourced from W14.1 audit §5)

Sourced from `v0.3-w14-test-coverage-audit.md` §5 ~48 shape-test failure classification. Failure classes routed to **v0.4-architectural-gap** disposition surface here. These are NOT W14.2-fixable per the audit's classification — fixing requires architectural rework named for v0.4.

### Exception A1 — v2-raw-heap aliasing class

- **Feature:** Class 1 — `TypedArray<T>` realloc invalidates aliased raw pointers held across iterations → VM Drop double-free (per CLAUDE.md "Known Constraints" v2-raw-heap-audit + W5 close cluster-1.5 audit)
- **Suites affected (uncovered behavior):** annotations_comptime, annotations_runtime, arrays_vectors, hashmap (`hashmap_filter_all_match`), objects (`object_function_value_call`), stochastic annotation_targets
- **Canonical anchor (test-side):** the 4 `#[ignore]`'d simulation tests at `bin/shape-cli/tests/stdlib/simulation.rs` (per CLAUDE.md "Known Constraints" line: "the 4 `bin/shape-cli/tests/stdlib/simulation.rs` ignored tests")
- **Productive-code site:** `crates/shape-vm/src/executor/objects/typed_array/` realloc-on-push surface + `crates/shape-vm/src/executor/vm_impl/stack/drop_with_kind` consumer
- **Why hard to test:** (h) the SIGABRT mid-test (`malloc_consolidate(): unaligned fastbin chunk detected`) is heap-corruption-class — not a soft test failure. Adding more tests does not address; the test ASSERTIONS would succeed if not for the SIGABRT crashing the test binary. Resolution requires architectural rework of `TypedArray<T>` realloc + aliased-pointer-tracking surface (per CLAUDE.md "Known Constraints" v2-raw-heap-audit).
- **Workaround-coverage:** 4 simulation tests `#[ignore]`'d to keep the workspace test gate green; other suites exhibiting the SIGABRT pattern are noted in `wave-3-baseline-classification.md` lines 266-277.
- **Disposition:** TRACKED-V0.4 → `v0.4-v2-raw-heap-aliasing-class-resolution` (per W14.1 audit §5 line 405 + §5 closing disposition).

### Exception A2 — stdlib JIT-compilation cache hang

- **Feature:** Class 2 — stdlib JIT-compilation caching (~118 stdlib functions per test) under serial execution (per CLAUDE.md "Known Constraints" shape-jit deep-tests gating)
- **Suites affected (uncovered behavior):** closures_hof, enums, error_handling, functions, generics, iterators, literals, lsp, modules_visibility
- **Productive-code site:** `crates/shape-jit/src/worker.rs` + stdlib JIT cache (~5 modules gated behind `deep-tests` feature: `mir_compiler::integration_tests`, `v2_array_tests`, `compiler::a1d2_tests`, `a1e_tests`)
- **Why hard to test:** (h) hangs (≥2-minute single-test wall-clock) under serial execution; the tests themselves are correctly structured — they hang in the JIT pre-compile path. Resolution = stdlib JIT cache architecture rework, not per-test fix.
- **Workaround-coverage:** `--features deep-tests` gating + `--test-threads=1` for the shape-jit suite per `justfile` test-tier shapes (`just test-deep`). Outside this gating, the affected suites still hang under unbounded runner-shape.
- **Disposition:** TRACKED-V0.4 → `v0.4-stdlib-jit-cache-arch` (per W14.1 audit §5 line 406 + §5 closing disposition).

## §4 SURFACE-AND-STOP — sub-cluster-batch architectural surfaces

These are NOT pre-classified DOCUMENTED-EXCEPTIONS — they are surfaces discovered while attempting the batch's other sub-clusters (G1/G3/A1). Per refusal #10 anti-deferral, the surfaces are NAMED + structured for supervisor disposition; the work-attempts that revealed them are documented in the W14.2-batch-1 close.

### Surface S1 — annotation_targets failures are V3-S5 ckpt-5 architectural, NOT W14.2-fixable

- **Feature:** Class 5 — annotation_targets 9/15 failure cluster (W14.1 audit §5 line 409 classified this as W14.2-FIXABLE)
- **Productive-code site:** `crates/shape-vm/src/compiler/comptime_target.rs:281` + `crates/shape-vm/src/executor/objects/typed_array/` `op_new_array(0)` consumer
- **Empirical at W14.2 batch HEAD:** The annotation_targets test failures at HEAD are V3-S5 ckpt-5 consumer-cascade tier 3 SURFACE panics (`comptime_target::nb_object_array: V3-S5 ckpt-5 consumer-cascade tier 3 SURFACE. the deleted typed-array-data TypedObject Arc<Buf<TypedObjectPtr>> result carrier DELETED ...`). 16 of 24 tests fail with this exact panic shape; the W14.1 audit's "9 passing + 15 failing pattern" classification (line 409) was based on a different prior-state behavior where the suite COULD complete without the V3-S5 architectural panic.
- **Why this is architectural, not W14.2-fixable:** The panic site is the W12-typed-array-data-deletion audit's named consumer-cascade rebuild that lands at V3-S5 ckpt-6 STRICT close per `docs/cluster-audits/w12-typed-array-data-deletion-audit.md` (per CLAUDE.md "Forbidden Patterns" cite). No test-side fix can satisfy the panic — the productive code surfaces `unimplemented!("REFUSED ON SIGHT: TypedArrayData resurrection under any rename (Refusal #1)")`.
- **Disposition:** RECLASSIFY → Class 5 split into Class 5A (the ~8 tests not triggering V3-S5 panic, still W14.2-fixable) + Class 5B (the 15-16 tests triggering V3-S5 panic, route to TRACKED-V0.4 `v0.4-v3-s5-ckpt-6-strict-close` — the same v0.4 cluster that owns the typed-array-data construction-site rebuild).
- **Surface authority:** This reclassification is structured for supervisor disposition; the W14.2-H1 deliverable surfaces honestly per refusal #10 anti-deferral, but the reclassification itself requires supervisor ratification before W14.2-G3 can claim "Class 5 retired".

### Surface S2 — async_concurrency callable-vs-value mismatch in compiler (NOT a missing-hook problem)

- **Feature:** Class 3 — async_concurrency 9/9 failure cluster (W14.1 audit §5 line 407 classified this as W14.2-FIXABLE per "missing-hook / wrong-trace-shape" framing)
- **Productive-code site:** `crates/shape-vm/src/executor/call_convention.rs:399::resolve_spawned_task` (callable validation) + `crates/shape-vm/src/compiler/expressions/misc.rs:651::compile_join_expr` (branch lowering) + `crates/shape-vm/src/compiler/expressions/advanced.rs:175::compile_async_let` (RHS lowering)
- **Empirical at W14.2 batch HEAD:** The async_concurrency failures are NOT missing-hook / wrong-trace-shape — they're a structural mismatch where the compiler emits raw expression values + SpawnTask, but `resolve_spawned_task` only accepts `NativeKind::Ptr(HeapKind::Closure)` or `NativeKind::UInt64` callables. Tests use `async let x = 42`, `join all { 1+2, 3+4 }`, etc. — plain non-callable values.
- **Disposition:** RESOLVED IN W14.2-G1 — extend `op_spawn_task` to detect non-callable values and mark them as pre-completed in the scheduler (the `TaskScheduler::complete()` API already exists for the external-completion path). `resolve_spawned_task`'s cached-result fast-path then returns the pre-completed value cleanly. Surface S2 is RECORDED for the audit trail but RESOLVED INSIDE THIS BATCH — not deferred.
