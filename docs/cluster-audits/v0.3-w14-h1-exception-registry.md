### Binding format (verbatim from W14.1 audit §6)

Every exception that drops a feature below the 99% line MUST cite:

1. **Feature ID** (W-series sub-cluster identifier).
2. **file:line span** of the uncovered productive code.
3. **Why hard to test** — concrete reason from:
   - (a) requires LSP client protocol harness
   - (b) requires Python/TS extension runtime env
   - (c) requires actual GPU / Vulkan / wgpu device
   - (d) requires async runtime under specific timing
   - (e) requires malformed bytecode injection surface that isn't safely test-instrumentable
   - (f) requires distributed wire transport active QUIC connection
   - (g) proc-macro expansion not measurable by tarpaulin
   - (h) other (cite specific technical blocker)
4. **Workaround-coverage if any** — integration-test harness location, smoke fixture, manual verification cadence, or "none" with rationale.

The exception list is NOT a graveyard — each entry must have a tracked
disposition (resolution sub-cluster ID OR v0.4 follow-up name OR
permanent-DOCUMENTED reason).
