## §1 — Methodology

For each of 145 extracted snippets:

1. **Parse-level:** does the snippet syntactically parse under the cumulative prelude?
2. **Symbol-level:** do all `module::function` calls resolve to declared stdlib functions (`pub builtin fn ...` in the corresponding `crates/shape-runtime/stdlib-src/core/*.shape`)?
3. **Runtime-level:** does VM + JIT execution complete with ec=0, or fail with a known classified surface (V3-S5 panic, missing-runtime-impl, permission gate)?

Spot-probes used a direct-call form (`from std::core::X use { fn }`) plus a direct `use std::core::X` form to disambiguate between import-style limitations and missing runtime implementations.

## §4 — (b)-class candidates for team-lead dispatch

**(b)-bundle-1: io path utilities missing runtime impl.** Declared in `core/io.shape` (`pub builtin fn join`, `dirname`, `basename`, `extension`, `resolve`) but no Rust impl registered. Probe `from std::core::io use { join }; let p = join("inbox")` → `error[SEMANTIC]: builtin function 'join' has no runtime implementation in module 'std::core::io'`. Impacts 2 native-io snippets (io-27 + io-04 in v1 extractor). **Disposition recommendation:** wire 5 stub impls (likely 1-2 hours; path-string ops are pure-Rust trivia) OR drop the declarations + remove from book.

**(b)-bundle-2: http functions options arg.** Doc heads say `options?` (optional, line 35/46/59/68/77/94/102/110); runtime signatures require `options: _` (positional, non-default). 9 snippets fail with `expected 2/3 arg(s), got 1/2`. **Disposition recommendation:** EITHER make options Optional in stdlib-src `core/http.shape` declaration + runtime (preferred — matches doc + usability) OR update book to always show explicit `{}` as 2nd arg (faster — pure book fix path).

**(b)-cross-slice-1: `as?` operator unimplemented.** Used in 3 json.mdx snippets (json-09, json-10, json-14), 1 advanced cookbook usage in book elsewhere. Parser fails on `expr as? T`. Belongs to slice A (language reference: type-cast operators). Cross-cite here because it blocks slice-F runnable verification.

**(b)-cross-slice-2: string-keyed object literals.** `{ "key": value }` rejected by parser. Affects http-10 (headers map). Belongs to slice A (object-literal syntax). May be intentional design (use `HashMap()` explicitly for non-identifier keys) — if so, the book fix is (a) [convert example to `let headers = HashMap(); headers.insert("Authorization", "Bearer x")`]. Need supervisor ruling.

**(b)-bundle-3: domain stdlib legacy type syntax.** `finance/types.shape`, `physics/types.shape`, `iot/types.shape` use `pub type X = { field: T; ... }` (= sign + semicolons) which current parser rejects. Modern syntax: `pub type X { field: T, ... }`. **Disposition recommendation:** classify (c) if domain stdlib is v0.4 territory; otherwise mechanical syntax migration (estimated 1-2 hours; non-load-bearing on the language).
