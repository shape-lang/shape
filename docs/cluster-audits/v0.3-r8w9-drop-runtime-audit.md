## 2. VM root-cause analysis

### 2.1 Repro 1 — `MakeRef Local outside any call frame`

Site: `crates/shape-vm/src/executor/variables/mod.rs::op_make_ref`,
ADR-006 §2.7 RefTarget construction:

```rust
Some(Operand::Local(local_idx)) => {
    let frame_index = self
        .call_stack
        .len()
        .checked_sub(1)
        .ok_or_else(|| {
            VMError::RuntimeError(
                "MakeRef Local outside any call frame".into(),
            )
        })? as u32;
    ...
}
```

Trigger condition: the compiler emits `MakeRef Local(slot)` for any typed-
field property access via `compiler/expressions/property_access.rs:252` and
`compiler/helpers_reference.rs:249`. When such a read fires at TOP-LEVEL
(outside any `fn`), `call_stack.len() == 0` and `checked_sub(1) -> None`.

Empirical confirmation: removing the Drop impl from repro 1 (so the only
SURFACE source is the block-scope's `print(f"opened {f.path}")` typed-field
read) reproduces the SAME error at the SAME instruction. The Drop impl is
NOT the proximate cause; the proximate cause is that `MakeRef Local`
forbids top-level frames.

```

ec=1
Error: Runtime error: MakeRef Local outside any call frame (line 1)
```

(`r8w9-block-noprop.shape` is repro 1 with the `impl Drop` block removed.)

### 2.2 Repro 2 — `MakeFieldRef base must reference a TypedObject; got Bool`

Site: `crates/shape-vm/src/executor/variables/mod.rs::resolve_typed_object_receiver`
arm `RefTarget::Local`:

```rust
if *kind != NativeKind::Ptr(HeapKind::TypedObject) {
    return Err(VMError::RuntimeError(format!(
        "MakeFieldRef base must reference a TypedObject; got {:?}",
        kind
    )));
}
```

Trigger condition: dumped bytecode for repro 2 (test-only helper
`dbg_dump_drop_in_fn_main_bytecode`, since reverted) shows the drop-scope
emitter at `fn main` produces:

```
30: DropLocal Local(2)         <- poisons slot c with NONE_BITS / kind=Bool
31: DropLocal Local(1)         <- poisons slot b
32: DropLocal Local(0)         <- poisons slot a
33: LoadLocal Local(2)         <- reads POISONED slot c
34: DropCall Property("R")     <- dispatches R::drop on Bool-kind bits
```

The V1.1C ownership-aware `DropLocal` pass runs BEFORE the legacy
`LoadLocal + DropCall` Drop-trait pass (see
`compiler/helpers.rs::pop_drop_scope` and `emit_drops_for_early_exit`).
`DropLocal` poisons the slot with the no-op Bool sentinel; the subsequent
`LoadLocal` reads the sentinel, and `DropCall` invokes `R::drop` on a
stale receiver. When `R::drop`'s body accesses `self.name`, the MakeRef
captures kind=Bool from slot 0 of the Drop frame, and
`resolve_typed_object_receiver` surfaces.

The pre-fix guard at `pop_drop_scope` (line 5128) skipped `DropLocal` for
`slot_is_boxed` or `slot_is_shared` — but NOT for slots whose type has a
user `Drop` impl. So heap-promoted (`PromoteToOwned`-via-Direct-storage)
typed-object slots with a user Drop got both `DropLocal` (poison) and
`DropCall` (which then dispatched on poisoned bits).

## 3. JIT root-cause analysis

Site: `crates/shape-jit/src/mir_compiler/ownership.rs::emit_drop`.

```rust
pub(crate) fn emit_drop(&mut self, place: &Place) -> Result<(), String> {
    // ... SharedCow path ...
    let disposition = self.refcount_disposition(place)?;
    match disposition {
        RefcountDisposition::Refcounted => {
            let val = self.read_place(place)?;
            let release_func = self.release_func_for_place(place);
            self.builder.ins().call(release_func, &[val]);
            self.null_place(place)?;
        }
        RefcountDisposition::Skip => { self.null_place(place)?; }
        RefcountDisposition::Skip_TypedCellCarrier => { ... }
    }
    Ok(())
}
```

The JIT `emit_drop` only releases the slot's refcount via the inlined
arc-release FFI helper and nulls the slot. There is NO dispatch into the
user's `Drop::drop` method — the bytecode interpreter's
`op_drop_call_impl` lookup of `Drop::TypeName::__default__::drop` in
`trait_method_symbols` has no JIT analogue.

Result: JIT silently elides every user Drop body. Both repros under JIT
print `opened ... / after block` resp. `body running / done` with NO
`Closed file: ... / drop: c / drop: b / drop: a` output. This breaks the
`book/v0.3/advanced/resource-management.mdx` documented RAII contract
(VM and JIT diverge on a documented language feature).

## 5. Fix dispositions

### 5.1 VM Part (a) — MakeRef Local top-level sentinel

`crates/shape-vm/src/executor/variables/mod.rs::op_make_ref` Local arm:
encode top-level frames as `frame_index = u32::MAX` instead of erroring.
Slot bits read from absolute slot index `local_idx`
(top-level `current_locals_base()` is 0).

Companion consumer-arm updates: `resolve_typed_object_receiver`,
`read_ref_target`, and `write_ref_target` Local arms route base_pointer=0
when `frame_index == u32::MAX`.

The sentinel survives across frame boundaries: a Drop method body that
received a ref captured against the top-level frame still resolves to the
correct stack slot. Sentinel choice (u32::MAX) cannot collide with real
frame indices: `call_stack` can have at most `usize::MAX` frames, but
`frame_index` is encoded as `u32`, and the largest meaningful real
`frame_index` is `call_stack.len() - 1` which is bounded far below
`u32::MAX` in any realistic execution.

### 5.2 VM Part (b) — `DropLocal` guard for user Drop slots

`crates/shape-vm/src/compiler/helpers.rs::pop_drop_scope` and
`emit_drops_for_early_exit`: skip `DropLocal` opcode emission when
`local_drop_kind(local_idx).is_some()`. The `DropCall` opcode's
`pop_kinded + call_function_with_nb_args` path is the sole releaser for
user-Drop slots; the V1.1C ownership-aware release would otherwise
poison the slot before `DropCall` reads it.

This mirrors the existing guard for `slot_is_boxed / slot_is_shared`
(boxed slots use the legacy `LoadLocal + DropCall` Arc release; shared
slots use `DropSharedLocal`).

### 5.3 JIT Part (b) — Drop-bearing-scope-exit preflight surface-and-stop

`crates/shape-jit/src/executor.rs::execute_with_jit`: refuse to JIT-
compile programs whose `trait_method_symbols` contains any `Drop::*`
entry. Returns `Err(...)` to trigger the existing `[jit-fallback]`
deopt path. The bytecode interpreter then runs the program with its
working `op_drop_call_impl` dispatch.

Path chosen: Path B (program-wide preflight check). Path A (per-
`emit_drop` slot-level detection) would require threading user-Drop
metadata into MirToIR slot state — non-trivial without an ADR. Path B
is bulletproof and ~6 lines.

Root-cause JIT Drop codegen (user-Drop trait-method dispatch at
`emit_drop` time) deferred to v0.4 per
`docs/v0.3-close-summary.md` §5.16 JIT-lowering followup workstream
(joining the aliased-CoW + imported-const-ident-eval + W17-marshal
bundle).
