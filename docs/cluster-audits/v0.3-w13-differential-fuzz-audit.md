## §1 Tooling design — cargo-fuzz vs custom harness

### §1.1 Cargo-fuzz (`cargo-fuzz` crate; libFuzzer or AFL backend)

**Mechanics.** `cargo install cargo-fuzz` adds a `fuzz/` directory with `Cargo.toml` + per-target `fuzz_targets/*.rs`. Each fuzz target is a Rust binary linked against libFuzzer (`#![no_main]` + `fuzz_target!(|data: &[u8]| { ... })`). The libFuzzer driver mutates `data` byte-by-byte under coverage-guided feedback (sanitizer + edge coverage instrumentation via `cargo +nightly fuzz`).

**Pros for Shape.**

- Industry-standard tooling; well-known triage commands (`cargo fuzz tmin`, `cargo fuzz cmin`, `cargo fuzz coverage`).
- Coverage-guided mutation finds bytecode-compiler bugs that hand-seeded corpus misses (e.g. obscure lexer states, parser-state-machine corner cases).
- Free dictionary support (`--dict=keywords.txt`) — seed mutations with Shape keyword list.
- Free crash-input minimization via libFuzzer's built-in `MinimizeCrash`.

**Cons for Shape.**

- **Input shape mismatch (load-bearing).** libFuzzer mutates random bytes; the W13 surface is **valid `.shape` source programs** whose VM execution and JIT execution diverge. Random bytes almost never form a syntactically-valid Shape program — signal-to-noise is dominated by parser/lexer errors that exit with `Error: parse error: ...` in BOTH modes (no divergence). The interesting surfaces (typed-array map+sum, closure-in-array, async, generics, comprehensions) almost never form from random bytes.
- **Wrong target surface.** The classic cargo-fuzz pattern fuzzes a **single Rust function** taking `&[u8]`. The W13 surface is the **end-to-end pipeline** `shape run --mode {vm,jit} <file>` — a subprocess with timeout, stdout capture, exit code. Wrapping this inside `fuzz_target!` adds subprocess-fork overhead per iteration (~10-50ms per invocation; libFuzzer expects ≥1000 iter/sec). Either we lose libFuzzer's iteration-rate advantage or we bypass the subprocess (which then bypasses the actual W13 surface).
- **ICE risk.** A panic in the bytecode compiler (a compile-time bug) aborts the libFuzzer driver — every panic becomes a "crash" report. Compiler ICEs are real bugs but they are NOT divergence findings; they pollute the W13 finding stream.
- **Triage burden.** Coverage-guided mutation produces inputs that look like `let \x00\xff \x80fn x((,,)` — minimization helps but the output is rarely close to a meaningful Shape program. Classifying findings into §5.1 residual classes becomes harder.
- **Nightly-Rust dependency.** `cargo +nightly fuzz` requires nightly. This adds a CI nightly-toolchain dependency that the rest of the workspace does not have (`Cargo.toml` workspace `rust-version = "1.86"` — stable). Adding nightly-toolchain to CI is a CLAUDE.md-relevant change (justified surfaces below).

**Empirical rate estimate (for Shape).** Industry data on language fuzzers: random-byte libFuzzer on a parser-heavy target with no grammar reaches ~0.1-1% syntactically-valid programs after corpus warmup. For Shape the strict typing + comptime + annotation surface narrows this further. Estimated effective valid-program rate without grammar-aware mutation: ~0.05-0.5%. Most CPU spent rejecting parse errors. (Reference: AFL++ on `lua` reaches ~2-5% with hand-tuned dictionary; Shape's strict typing makes it harder.)

### §1.2 Custom harness (Rust binary in `tools/shape-fuzz/`)

**Mechanics.** A new workspace member `tools/shape-fuzz/` (binary crate, mirrors `tools/shape-test/`). Reads corpus files from `tools/shape-fuzz/corpus/<domain>/*.shape` (hand-seeded per §3 below). For each corpus file:

1. Spawn `target/release/shape run --mode vm <file>` with 30s timeout via `std::process::Command`. Capture stdout-tail-1 + exit code (mirrors §3.2 of W12 close).
2. Spawn `target/release/shape run --mode jit <file>` identically.
3. Compare per §2 below. Record divergences to `tools/shape-fuzz/findings/<timestamp>-<sha256-of-source>.txt` with the source program + both outputs + classification.
4. Mutation-grow corpus: per corpus seed, apply a fixed small mutation set (replace literal value, swap operator, drop statement, insert no-op variable rebind) bounded to ~5-10 mutations per seed per nightly run. Mutated programs that exercise NEW parser-trees are kept as new corpus; mutated programs that re-execute identically to the seed are dropped.
5. Exit code: 0 if no NEW divergence (divergences in the §4 negative-corpus subdirectory are EXPECTED and excluded); non-zero if new divergence found.

**Pros for Shape.**

- **Surface matches W13 charter exactly.** Subprocess invocation IS the W13 surface — no signal-loss.
- **Stable Rust only.** No nightly toolchain dependency; no new CI complexity. Lives in the existing `tools/` workspace family.
- **Hand-seeded corpus gives explicit per-domain semantic guarantees.** Each seed is a known-valid Shape program with a known canonical output (per §3 inventory). Coverage of W12 fall-through class + tier-up class + the §5.1 residual JIT classes is explicit, not stochastic.
- **Triage is one-click.** A divergence finding directly cites the source program + both outputs + a class label. No minimization step needed for hand-seeded corpus. For mutation-grown corpus, a 50-line custom minimizer (drop statements until divergence disappears, then bisect) suffices.
- **Refusal-discipline-aligned.** No bridge/probe/helper/hop/translator/adapter/shim framing required for the harness — the entry-points are `run_corpus`, `compare_outputs`, `classify_divergence`, `record_finding`. Concrete API.
- **CLAUDE.md-quiet.** No CLAUDE.md modifications required.

**Cons for Shape.**

- **No coverage-guided mutation.** Mutation is dumb (per-mutation-rule); the harness won't discover lexer/parser corner cases libFuzzer would. **Mitigation:** parser/lexer is unit-test-tested in `crates/shape-ast/`; the W13 surface is execution divergence at the bytecode/JIT layer, where coverage-guided is less useful (the bytecode compiler is mostly deterministic per AST shape, and JIT divergence is mostly per-opcode-arm).
- **Manual corpus maintenance.** Adding a new domain means adding a corpus subdirectory + 5-10 seed programs. **Mitigation:** §3 below front-loads this work; per-domain seed sets are bounded (no combinatorial blowup).
- **Reinventing the minimizer.** Standard cargo-fuzz `tmin` is free. **Mitigation:** custom minimizer is ~50 LoC bounded scope — a bisect-by-statement-removal loop suffices for the W13 grammar shape.

### §1.3 Recommendation — custom harness

**RECOMMENDED: custom harness (option §1.2).**

Reasoning (3 sentences):

1. The W13 surface is **subprocess-level differential execution of valid `.shape` programs under `--mode vm` vs `--mode jit`** — exactly the surface the §1.2 custom-harness exercises directly; cargo-fuzz's coverage-guided random-byte mutation produces ~99.5%-invalid-program noise on a strictly-typed grammar with comptime + annotations, and inverting that ratio would require a grammar-aware fuzzer (custom work either way).
2. The harness lives in the existing `tools/` workspace family alongside `tools/shape-test/` + `tools/shape-lsp/` + `tools/xtask/` — no new build-system dependency, no nightly-toolchain bump, no `fuzz/` directory at workspace root (CLAUDE.md-quiet).
3. Per-domain hand-seeded corpus + bounded mutation is sufficient to catch the W13 surfaces enumerated in §5.1 (10 named residual JIT coverage classes) + the W12 fall-through class — coverage-guided mutation would find compiler ICEs (real bugs but out of W13 scope per §0) and signal-pollute the divergence-finding stream.

**No CLAUDE.md modification required for §1.2 (audit-only deliverable).**

**No new dev-tools dependency required for §1.2** beyond `std::process::Command` + the existing `target/release/shape` binary.

**Architectural cost surface (none expected):** §1.2 adds one new workspace member `tools/shape-fuzz/` (binary crate). Mirrors existing `tools/shape-test/` shape. No new dependency on a fuzz-engine crate. No new ADR-006 amendment.

## §2 Differential-execution semantics — what counts as divergence

**Canonical compare** (per W12 close §3.1 corrected-harness shape; per `docs/cluster-audits/v0.3-w12-jit-mode-semantics-close.md:198-207`):

```bash
out_vm=$(timeout 30 ./target/release/shape run --mode vm <file> 2>/dev/null | tail -1); ec_vm=$?
out_jit=$(timeout 30 ./target/release/shape run --mode jit <file> 2>/dev/null | tail -1); ec_jit=$?
```

The harness compares `(out_vm, ec_vm)` vs `(out_jit, ec_jit)` per the rules below.

| # | Divergence class | Trigger | Action | Classification |
|---|---|---|---|---|
| 1 | **stdout-tail divergence** | `out_vm != out_jit` AND `ec_vm == ec_jit == 0` | RECORD as divergence; classify per §5.1 class or NEW class | HIGH-SIGNAL |
| 2 | **exit-code divergence** | `ec_vm != ec_jit` (e.g. `0` vs `1`) | RECORD as divergence; classify | HIGH-SIGNAL |
| 3 | **runtime-error asymmetry** | One mode `ec=1` with stderr Error; other mode `ec=0` with clean output | RECORD as divergence (asymmetric crash); classify | HIGH-SIGNAL |
| 4 | **dual runtime error** | Both `ec=1`, stderr Error messages differ | OPTIONAL record (low priority — likely both reject the program; not output-divergence) | LOW-SIGNAL |
| 5 | **dual timeout** | Both timeout at 30s | DROP (infinite loop in test program; not a divergence) | NOISE |
| 6 | **single timeout** | One mode timeouts at 30s; other completes | RECORD as divergence (JIT compile cost OR VM-only infinite-loop OR JIT-only infinite-loop) | MEDIUM-SIGNAL |
| 7 | **tier-boundary divergence** | Same program iterated 0/99/100/9999/10000 times; output differs across tier boundary | RECORD as divergence (tier-up bug) | HIGH-SIGNAL |
| 8 | **`[jit-fallback]` info emission** | `--mode jit` stderr contains `[jit-fallback]` line; stdout still matches VM stdout; both `ec=0` | DROP (NOT a divergence — this is the W12 binding shape; fall-through working as designed) | EXPECTED |

### §2.1 Critical classification rule: `[jit-fallback]` is NOT divergence

Per `crates/shape-jit/src/executor.rs:151` + W12 close §1.1: on JIT compile failure, the executor falls through to `BytecodeExecutor::execute_program` (which is exactly what `--mode vm` runs). When fall-through fires, the JIT-mode stdout MATCHES the VM-mode stdout by construction. The `[jit-fallback]` line is emitted to **stderr** (info-level diagnostic per W12 §2 mission item 3). Since the harness pipes `2>/dev/null`, the diagnostic is dropped from the compare. **Result: same `(out, ec)` in both modes → NOT a divergence.**

This means the W13 harness is **insensitive to JIT compile-failure surfaces** — it cannot distinguish "JIT compiled successfully" from "JIT failed compile + fell through to interpreter". This is intentional per the W12 binding shape. If a future W13 wave wants to surface fall-through events (e.g. to measure JIT coverage), it should parse stderr separately — distinct workstream, NOT a W13 divergence trigger.

### §2.2 Tier-boundary divergence design

The §2 row 7 tier-boundary divergence test wraps each per-domain seed program in a counted loop (`for i in 0..N { call_seed_fn(i) }` shape) at N ∈ {0, 99, 100, 9999, 10000} to exercise the T1@100 (per `crates/shape-vm/src/tier.rs:33`) + T2@10000 (per `crates/shape-vm/src/tier.rs:34`) thresholds. A divergence at N=100 vs N=99 indicates a Tier-1 baseline JIT semantics bug; at N=10000 vs N=9999 indicates a Tier-2 optimizing JIT bug. The W12 close §4 `t3-hot-cond.shape` SURFACE (W12-followup-jit-cond-int-negation) is exactly this class — verified at HEAD `e6b14a90` produces VM `-62500` vs JIT `9223372036854775558` for a 500-iter `if-else-negation` loop.

### §2.3 Out-of-scope per §0

Timing-divergence, memory-divergence, within-single-mode-determinism: NOT classified by the harness. The harness wall-clock-budgets every invocation at 30s but does not record per-invocation timing.

## §4 Corpus seeding strategy

### §4.1 Hand-seeded initial corpus (golden + negative)

Per §3, each domain ships 5-10 hand-seeded programs classified as either **(g) golden** (known VM == JIT at HEAD; regression sentinel) or **(n) negative** (known-divergent per §5.1 residual class; serves as harness self-test PLUS regression-detector when the residual class fix lands — at which point the seed flips (n) → (g) and the harness now ensures the convergence is preserved).

Negative-corpus seeds at HEAD `e6b14a90`:

| Seed | §5.1 class | Empirical divergence at HEAD |
|---|---|---|
| a10 | #6 W12-followup-jit-cond-int-negation | VM `-62500` vs JIT `9223372036854775558` (verified at HEAD via 500-iter `if-else-negation` loop) |
| c09 | #10 W11-followup-jit-spread-expand | Per W11-fup-C close §4 — JIT pushes inner array's raw pointer as single element; fall-through MAY converge (if fall-through fires) — corpus harness records actual divergence shape |
| c10 | #2 W11-followup-slice-classify | Per W11-jit-new-array close §4 Class A' — JIT-mode IndexAccess-slice Aggregate fallback; SURFACE may fire OR fall-through may converge |

The negative seeds anchor the harness against the §5.1 residual classes. As each class is closed (closure-wave W11-fup-D + W11-fup-E etc. land), the corresponding seed flips classification (n) → (g) and the harness now permanently regression-protects the fix.

### §4.2 Mutation-grown corpus

Per nightly run, the harness applies a bounded mutation set per seed:

1. **Literal-value substitution.** Replace one int literal with `0` / `1` / `-1` / `i64::MAX` / `i64::MIN`. Replace one number literal with `0.0` / `NaN` / `inf` / `-inf`. Replace one string literal with `""` / `"\\0"` / a 1KB random ASCII string.
2. **Operator swap.** Replace one `+` with `-` / `*` / `/`; one `<` with `<=` / `>` / `>=`; one `&&` with `||`.
3. **Statement drop.** Remove one statement from the body of a function (if the AST has >1 statements).
4. **No-op rebind insertion.** Insert `let _unused = <expr>` before a statement (uses an existing in-scope variable as `<expr>`).
5. **Tier-up wrap.** Wrap any pure-function call in a loop iterated N times for N ∈ {99, 100, 9999, 10000} — exercises tier-boundary divergence per §2.2.

Mutations are applied SEQUENTIALLY per seed (one mutation per derived program); fan-out is bounded to ~5 derived programs per seed per nightly run. Derived programs that fail to parse OR fail to type-check are dropped silently (not a divergence). Derived programs that pass parse + type-check but produce the same `(out, ec)` in both modes are kept as a NEW golden corpus entry IF they exercise a NEW parser-tree shape (heuristic: AST node-count differs from seed); otherwise dropped. Derived programs that produce divergence are recorded per §5 triage workflow.

The mutation set is intentionally NARROW — coverage-guided mutation is explicitly OUT OF SCOPE per §1.3 recommendation. The hand-seeded corpus + bounded mutation is the W13 surface; richer fuzzing is a v0.4+ candidate.

### §4.3 Corpus growth discipline

- **Seeds added by closure-waves only.** W13.2-N waves land corpus seeds with implementation code; ad-hoc corpus additions outside a wave are refused (corpus drift is a defection-attractor — refuses cumulative-state opacity per W12 close §11 imprecision discipline).
- **Negative corpus entries are NAMED with their §5.1 class.** No anonymous negative corpus.
- **Corpus minimization runs per nightly** — a custom-minimizer pass drops corpus entries whose AST is a subset of another corpus entry's AST (deduplication). Bounded to 30s wall-clock per nightly.

## §5 Triage workflow — when fuzz finds a divergence

### §5.1 Minimization

For a divergent program P found by the harness:

1. **AST-subset bisect.** Tokenize P; bisect by removing statements one at a time (binary search). Smallest P' that still diverges is the minimized reproducer. Bounded to 50 bisect iterations per finding (≈ 50 × 60s = 50 min wall-clock per finding worst-case; typically resolves in 5-10 iterations for hand-seeded P).
2. **Per-statement validation.** After removal, run `shape run --mode vm <P'>` to confirm P' still parses + type-checks + executes; if not, undo the removal and try a different bisect arm.
3. **Output.** Minimized P' + minimized divergence `(out_vm, ec_vm) ≠ (out_jit, ec_jit)` + bisect depth.

No `cargo fuzz tmin` dependency — custom minimizer per §1.3 reasoning.

### §5.2 Classification

For a minimized reproducer P':

1. **Pattern-match against §5.1 residual classes** (`docs/v0.3-close-summary.md` §5.1 enumeration: 10 named follow-ups W11-followup-{open-range-iterator, slice-classify, unop-bitnot, instanceof-classify, jit-unary-neg-int64} + W12-followup-jit-cond-int-negation + W10-followup-named-args-default-value + W17-narrow-follow-up-spread + W11-followup-comprehension-iterable-element-kind + W11-followup-jit-spread-expand). If P' matches a known class, ASSIGN to that class; record finding in negative-corpus subdirectory with class name.
2. **If no §5.1 match: SURFACE-AND-STOP per CLAUDE.md.** New divergence class = new follow-up sub-cluster candidate. Surface to team-lead via close-doc with: (a) minimized reproducer P', (b) AST shape, (c) failing tier (T0 / T1 / T2), (d) hypothesized failure mode (kind-stamp gap / Aggregate-fallback / MIR Rvalue arm / JIT FFI body / etc.).
3. **Refuse on sight.** Per CLAUDE.md §Forbidden Rationalizations: NEVER classify a new divergence as "edge case", "documented FFI-boundary helper", "fallback for one case", "compatibility layer". A new divergence is a new bug class — name it after the failing surface, surface for disposition.

### §5.3 Reproducer ceremony

When a divergence is classified (per §5.2 step 1 OR resolved per §5.2 step 2):

1. **Commit reproducer to negative corpus.** New file `tools/shape-fuzz/corpus/<domain>/<class-name>.shape` with `// CLASS: <class-name>` header comment + minimized program body.
2. **Cite class in commit message.** `tools/shape-fuzz: add reproducer for <class-name> (W13 finding)`.
3. **AGENTS.md row appended.** W13-finding-NNN row with class name + minimized reproducer SHA-256.
4. **When fix lands (closure-wave for <class-name>):** flip negative-corpus seed (n) → (g) in `<domain>/<class-name>.shape` header (`// CLASS: <class-name> (RESOLVED at <commit-hash>)`); fix sub-cluster's close doc references the seed file.

## §6 CI integration shape

### §6.1 Cadence

**NIGHTLY ONLY.** Per `docs/cluster-audits/phase-3-team-lead-handover.md:42-47` test execution policy ("Full suite + fuzz = NIGHTLY ONLY (not per-commit; not per-merge-ceremony unless audit-day batch merge)"). The W13 fuzz harness is NOT a per-commit gate; NOT a merge-ceremony gate (except at audit-day batch merges per coverage gate convention). NOT a release gate either at v0.3.0 (single-fixture smoke matrix per §S0 remains the merge-gate).

### §6.2 CI job shape

New `.github/workflows/nightly-fuzz.yml`:

```yaml
name: nightly-fuzz-differential
on:
  schedule:
    - cron: '0 4 * * *'  # 04:00 UTC nightly
  workflow_dispatch:     # on-demand
jobs:
  fuzz:
    runs-on: ubuntu-latest
    timeout-minutes: 180  # 3-hour wall-clock cap; per-domain timeout below
    steps:
      - uses: actions/checkout@v4
      - name: Install Rust stable
        run: rustup toolchain install stable
      - name: Build release binary
        run: cargo build --release --bin shape
      - name: Run differential fuzz
        run: cargo run --release -p shape-fuzz -- \
          --corpus tools/shape-fuzz/corpus \
          --domains arithmetic,collections,closures,patterns,async,generics,fallthrough \
          --per-domain-timeout 1200 \
          --mutations-per-seed 5
      - name: Upload findings
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: fuzz-findings-${{ github.run_id }}
          path: tools/shape-fuzz/findings/
          retention-days: 30
```

### §6.3 Per-domain timeout

20 min per domain (1200s) × 7 domains = 140 min nightly budget. Cap at 180 min via `timeout-minutes`. If a domain exceeds 20 min, that domain's run is killed (SIGKILL via subprocess); findings up to kill are still recorded; subsequent domains still run. Per-seed timeout is the 30s the harness already enforces.

### §6.4 Corpus + findings persistence

- **Corpus seeds:** `tools/shape-fuzz/corpus/<domain>/*.shape` — committed to git, version-controlled with code (no S3, no git-LFS, no artifact server — corpus is small per §3.8 ≈ 10 KB initial + ~50 KB mutation-grown bounded). Each closure-wave commit may add corpus entries (per §4.3 discipline).
- **Findings:** `tools/shape-fuzz/findings/<timestamp>-<sha>.txt` — NOT committed; uploaded as GitHub Actions workflow artifact with 30-day retention (sufficient triage window). Triage cadence: team-lead reviews artifacts at the daily standup pattern, OR when nightly CI red-fails (job exits non-zero per §1.2 step 5).

**Recommended persistence: GitHub Actions artifact + 30-day retention** (no separate S3/git-LFS dependency). Surface-and-stop if user prefers a separate store (e.g. shape-registry self-hosted artifact endpoint); deferred per "no new dev-tools dependency" per §1.3.

## §8 Surfaces

**SURFACE-AND-STOP #1:** **GitHub Actions artifact retention as findings-store.** §6.4 picks GitHub Actions artifact upload (30-day retention) over alternatives (S3, git-LFS, shape-registry artifact endpoint). If the user / team-lead prefers a long-retention store, this choice flips and §6.2 + §6.4 need amendment in the W13.4 close. Default ratification: artifact upload sufficient pending divergent disposition.

**SURFACE-AND-STOP #2:** **Mutation engine bounded to 5 mutations per seed per nightly.** §4.2 picks 5. Could be 1, 10, 100. Higher counts widen surface but blow nightly budget (§3.8 estimates 60-min real for 5 mutations × 50 seeds; 100 mutations × 50 seeds ≈ 20-hour budget, exceeds nightly window). Default ratification: 5 mutations per seed per nightly; adjust at W13.3 close per measured wall-clock.

**SURFACE-AND-STOP #3:** **Negative-corpus convention.** §4.1 picks `(n)`-labeled corpus seeds as "expected divergence". An alternative is to maintain divergent seeds in a sibling `tools/shape-fuzz/known-divergences/` directory, EXCLUDED from the main corpus run. Pro `corpus/`-sibling: divergences self-document and flip on fix; pro `known-divergences/`-separate: corpus directory is purely golden + simpler harness exit-code logic. Default ratification: §4.1 single-corpus with `(n)` header label.

**No ADR-006 amendment surfaced.** The harness does not introduce a new carrier shape, new opcode, new ABI, new dispatch site. It observes existing CLI output.
