### Class C: Module namespace dispatch is documented but lacks runtime schema (a)

The post-W3.2-B fix-wave rule (slice-B audit `7eed25f9`-era) standardized module
calls on the `::` syntax: docs use `set::new()`, `stochastic::brownian_motion(...)`,
`rolling::rolling_mean(...)`, etc.

At HEAD `605ad98e`, this dispatch is **enforced by the compiler** ("Module
namespace calls must use `::`. Replace `set.new` with `set::new(...)`") but
**not backed by a runtime schema** for pure-Shape modules. The error is:

```
error[SEMANTIC]: module namespace 'set' is not typed. Missing module schema for export 'new'
```

The workaround that works empirically: `from std::core::set use { from_array, len }`
then `from_array([...])` (bare-name invocation). This is a documented stdlib
shape (`from..use` import) but the chapter examples use module-qualified
`module::fn(args)` form which fails.

**Two acceptable fixes**, both class (a) (doc-side):
1. Rewrite every doc snippet to `from std::core::<mod> use { <fn>, ... }` then
   bare-name calls. Already done in `core/math.mdx` and `core/random.mdx` so this
   matches the slice-B fix shape.
2. OR write the module schema for pure-Shape stdlib so `module::fn(...)` works.
   That is a code-side change (class b); slice E does not authorize it.

This audit recommends path (1) per slice-B precedent.

### Class E: HashMap key-kind discriminator gap (b — pre-existing)

`HashMap.set(int_key, ...)` and `HashMap.set(string_key, ...)` both fail with
`HashMap key must be a string (got kind Int64)` / `(got kind StringV2)`. Set
module is layered atop HashMap so `set::from_array([1,2,3])` and
`set::from_array(["a","b","c"])` BOTH fail — `set` is effectively unusable
through the documented API.

This appears to be a pre-existing W17.3-4.3 class-shift adjacent surface (the
"Set<int> keys-must-be-string + pass-by-value field-read mutation" class-shift
called out in close-summary criterion B row). Class (b); list in §4.

### b-3: HashMap key-kind discriminator gap (MEDIUM — blocks set chapter end-to-end)

layered atop HashMap so the entire `core/set.mdx` chapter fails end-to-end even
after the (a) doc-form fixes.

### b-4: W17-marshal-return-arms factory side (MEDIUM — blocks state + transport + snapshot)

workaround works.
