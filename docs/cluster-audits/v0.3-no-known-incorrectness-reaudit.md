# v0.3 NO-KNOWN-INCORRECTNESS re-audit — classification

**Binding (user, 2026-05-20):** "ANY incorrect and known behaviour needs to
be fixed before 0.3." Every v0.4-deferred candidate, every pre-existing
shape-test failure, every CLAUDE.md Known Constraint, and every
named-but-unverified surface re-audited and re-classified.

**Classification rule:**
- KNOWN-INCORRECT → v0.3-gating: crashes (SIGSEGV/SIGABRT/panic), VM/JIT
  divergence, wrong results, double-free/UAF/memory-unsafety, UB,
  silent-wrong-output.
- INCOMPLETE-BUT-CORRECT → v0.4: missing docs, unimplemented features
  that error cleanly, feature-completeness gaps.
- POLISH/REFINEMENT → v0.4: bounded-sound transitional states, internal
  renames, per-container refinements of already-sound carriers.

**Method:** 4 parallel read-only audit agents, empirical reproduction at
HEAD `71a88e4b` (release binary). Three single-sourced findings
team-lead spot-confirmed. Not classified from audit-text.

## §1 v0.3-gating — KNOWN-INCORRECT (new dispatch territory)

Grouped into 5 fix-families.

### Family α — TypedArray vacated-arm crash (1 root cause, ≥2 triggers)

`clone_with_kind` hits `unreachable!()` on `HeapKind::TypedArray`
(ordinal 8) at `crates/shape-vm/src/executor/vm_impl/stack.rs:97`. The
W12-audit retirement comment asserts "no live slot bits carry this kind
post-V3-S5 ckpt-4" — empirically FALSE.

- **α1** closure capturing an `Array<T>` value → VM Rust panic (ec=101)
  + JIT SIGABRT (ec=134). Repro `|| data.sum()` over `let data=[10,20,30]`.
- **α2** struct field of type `Array<T>`, read path → VM panic at
  `op_deref_load`→`clone_with_kind`, JIT SIGABRT / garbage. Repro
  `type Bag{items:Array<int>}; Bag{items:[1,2,3]}.items[0]`. Construction
  works; only the array-typed-field READ crashes.

### Family β — v2-raw-heap aliasing / allocator-pair memory corruption

Memory-unsafety family. Root-cause map only partially known — needs an
audit-first pass before fix-dispatch.

- **β1** `RefTarget::TypedField` double-free (the R5c-2-β-β-(d)-followup).
  ROOT CAUSE CONFIRMED, NARROW: `RefTarget::TypedField.receiver` is a
  stale `Arc<TypedObjectStorage>` (`crates/shape-value/src/reference.rs:78-82`)
  but production allocates v2-raw `_new`; the 3 `resolve_typed_object_receiver`
  arms (`crates/shape-vm/src/executor/variables/mod.rs` ~2790/2808/2829)
  do `Arc::increment_strong_count`+`Arc::from_raw` on `_new` bits →
  corrupts 16 bytes before the allocation → ~4-6% double-free. Fix:
  migrate receiver to the existing `TypedObjectPtr` v2-raw carrier.
  2 files, 1 variant + ~5 arms. Single checkpoint.
- **β2** `smoke_test::typed_object_property_assignment` — VM assertion-
  abort at `variables/mod.rs:2991`: "DerefStore: TypedField
  field_kinds[1]=Null drift vs RefTarget captured kind Int64". SAME
  `RefTarget::TypedField` site as β1 — likely the same fix sweeps it.
- **β3** `strings_formatting` suite — SIGABRT (signal 6) heap corruption.
- **β4** Class-1 v2-raw aliasing — SIGABRT/`misaligned pointer dereference`
  across annotations / arrays_vectors / hashmap / objects suites.
- **β5** `hashmap_group_by_*` — SIGSEGV (signal 11) via `f"{v}"` interp.
- **β6** JIT `Set.add()` with a non-string key → SIGSEGV (ec=139). VM
  has the runtime key-type guard; JIT does not.

### Family γ — JIT codegen garbage / VM-JIT divergence

- **γ1** JIT `[...a]` array-spread → non-deterministic garbage (varies
  per run — uninitialized memory read). VM errors cleanly.
- **γ2** JIT open-range slice `xs[2..]` → garbage. VM errors cleanly.
- **γ3** JIT prints integer-valued `number` without the decimal:
  `print(3.0)` → VM `3.0` / JIT `3`. Silent VM/JIT divergence.
- **γ4** `array_destructuring_rest` — VM/JIT divergence: VM runtime
  error, JIT silently prints a scalar (`2`) instead of `[2,3,4]`.
- **γ5** JIT i64 division SIGILL — div-by-zero AND `i64::MIN/-1` both
  trap (Cranelift `sdiv`, `crates/shape-jit/src/mir_compiler/rvalues.rs:788-799`
  `TrapCode::User(0)`). Surfaced by R5c-2-β-γ checkpoint (a).

### Family δ — unimplemented builtin `todo!()` panics

`crates/shape-vm/src/executor/vm_impl/builtins.rs:793-817` — all 6
DateTime constructors (`DateTimeNow/Utc/Parse/FromEpoch/FromParts/
FromUnixSecs`) plus `MatFromFlat` and `MakeTableFromRows` are `todo!()`
stubs → panic (ec=101) VM and JIT. Spot-confirmed: `DateTime.parse(...)`.

### Family ε — wrong-result inference / monomorphization

- **ε1** nested function calls with unannotated params → silently wrong
  results. Spot-confirmed: `double(double(10))` over `fn double(x){x*2}`
  → `2e-321` (expected 40); `add_five(37)`→5; 3-deep→4.0. VM==JIT both
  wrong (kind-confusion, not overflow — NOT swept by R5c-2-β-γ (a)/(c)).
- **ε2** `.sort()` → stack overflow. Spot-confirmed: `[3,1,2].sort()`
  infinite-recurses, VM==JIT.
- **ε3** `.reduce()` → silent no output. `[1,2,3].reduce(0,|acc,x|acc+x)`.

### Borderline
- annotation `before`/`after` hooks → VM/JIT divergence (VM
  `op_new_array` SURFACE, JIT runs correctly). Shares root with the
  `op_new_array` cascade. Supervisor disposition requested.
