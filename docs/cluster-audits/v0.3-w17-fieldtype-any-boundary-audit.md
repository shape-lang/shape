parallel-`field_kinds` track (§3.A) or by an explicit `Any → compile
error` projection (§3.D).

### §3.A The W17-comptime-vm-dispatch parallel-kind track (BOUNDED — ALLOWED)

`crates/shape-vm/src/executor/typed_object_ops.rs:204-236` documents
the resolution path: `push_field_value_with_kind` sources `NativeKind`
from `TypedObjectStorage::field_kinds[i]` rather than from the
operand-encoded `field_type_tag`. ADR-006 §2.7.26
(W17-comptime-vm-dispatch, 2026-05-12) explicitly authorizes this for
`FIELD_TAG_ANY` sites where the storage's parallel track carries a
concrete kind.

The dispatch branch at `op_get_field_typed` (`typed_object_ops.rs:522-537`):

```rust
let result = if *field_type_tag == FIELD_TAG_ANY
    && field_index < storage.field_kinds.len()
{
    push_field_value_with_kind(
        self,
        &storage.slots[field_index],
        storage.field_kinds[field_index],
    )
} else {
    push_field_value(...)
};
```

This IS the §2.7.5 producer-side stamp — the producer stamps the
concrete kind at storage construction (in the `field_kinds` track) at
the same time the bits are written. The schema-side `FieldType::Any`
operates as the "this is heterogeneous-by-design" marker that gates the
dispatch into the parallel-kind path.

### §3.B Operand-encoding writer / reader (BOUNDED — allowed)

`typed_object_ops.rs:63` writes `FIELD_TAG_ANY` for `FieldType::Any`
fields; `typed_object_ops.rs:85-88` round-trips `FIELD_TAG_ANY` back to
`FieldType::Any`. The operand IS the canonical encoding;
`field_tag_to_heap_native_kind` (`:99-115`) returns `None` for
`FIELD_TAG_ANY` per Q14 §2.7.13 — "no statically-sourceable
NativeKind, producing emitter must stamp a concrete tag". The §3.A
parallel-kind track IS that stamp.

### §3.C MakeFieldRef fast-path skip (BOUNDED — W15.2-LANG-8 discipline)

`property_access.rs:226-236` + `assignment.rs:504-511` document the
W15.2-LANG-8 fix: when the field's `field_type_info` is
`FieldType::Any`, skip the MakeFieldRef + DerefLoad/DerefStore fast
path and fall through to `GetFieldTyped` / `SetFieldTyped` which
consult the parallel-`field_kinds` track. This IS the same §3.A
resolution path at the compiler-emission side.

### §3.D Comptime-literal projection refusal (BOUNDED — explicit error)

`comptime.rs:1053-1064` documents `field_kind_for_readback` as
explicitly refusing `FieldType::Any` projection — "FieldType::Any
cannot be read back without kind metadata". This IS the canonical
§2.7.5 refusal at the comptime literal-projection layer.

### §3.E Annotation-projection refusal (BOUNDED — explicit None)

`expressions/mod.rs:1642` returns `None` from
`field_type_to_annotation` for `FieldType::Any` — the caller falls
back to the inference engine. Legitimate; mirrors `to_native_kind`
refusal at `field_types.rs:184`.

### §3.F JSON / CSV marshal-layer fallback (BOUNDED — typed Json-enum carrier)

`json.rs:307` + `csv_module.rs:218` document the marshal-layer
fallback: `FieldType::Any` schema fields receive a typed
`Json::Object` HeapValue per ADR-005 §1 single-discriminator. The
JSON-enum tree IS strict-typed at the heap layer; the schema-side
`Any` is the carrier-tier marker that gates into the `Json::*` enum
variant per `json_value.shape`.

## §4 Per-site disposition for each FALLBACK site

Three disposition classes per the audit prompt:

- **(a)** fix fallback to propagate-unresolved-to-verification-pass
- **(b)** emit immediate compile error at site
- **(c)** intermediate-only — no change

(Plus a fourth class added by this audit: **(d)** ALLOW with named
exception class — the parallel-`field_kinds` track IS the §2.7.5 stamp.)

### §4.D.1 — `field_types.rs:259/270` `Option`-as-Any (Classes (a)+(b))

The `is_optional` and `SemanticType::Option(_)` arms return `Any`
because "Optional values use NaN boxing". This is the deleted
NaN-boxing rationalization preserved under the schema layer. Two valid
dispositions:

- **(a) PROPAGATE.** Introduce `FieldType::Option(Box<FieldType>)`
  variant. The `Option<T>` payload carries the inner type explicitly
  through the schema layer. Slot storage stays NaN-boxed at the bits
  level via the parallel-`field_kinds` track (the kind for `None` is
  `NativeKind::Null`; for `Some(x)` the inner `T`'s kind).
- **(b) ERROR.** Optional types reaching `semantic_to_field_type`
  unresolved are themselves a soundness issue — emit compile error
  E#### at the boundary.

Recommendation: (a) — the Option payload IS a legitimate
heterogeneous-discriminated-union case that the schema should preserve
explicitly. Mirrors the §4.D.14 enum-payload exception (which already
uses the parallel-`field_kinds` track at storage time per §2.7.26).
SURFACE-AND-STOP item §9.B.1.

### §4.D.2 — `field_types.rs:274` `_ =>` fall-through (Class (b))

The "Default to Any for complex types" arm is the canonical defection
attractor. The fall-through hides which `SemanticType` variants are
unhandled, which means new variants silently get NaN-boxed instead of
landing in the per-variant arm. **(b) ERROR.** Replace with explicit
arms for every `SemanticType` variant; any unreachable arm gets
`compile_error!()` or `unreachable!()` at the lowering layer.

### §4.D.3 — `collections.rs:487/496` inline-object FieldType inference (Class (a))

`infer_field_type_from_expr` at `collections.rs:13-26` only handles
literals. **(a) PROPAGATE.** Strengthen the lowering to surface the
unresolved-element-type as a structured `SemanticError` rather than
returning `None` (which fallthroughs to `unwrap_or(FieldType::Any)`).
Mirrors the W15.2-LANG-8 producer-side stamp discipline.

### §4.D.4 — `collections.rs:953/982` struct-literal expected-fields fallback (Class (b))

The W15.2-LANG-8 fix at `collections.rs:904-986` already routed the
common cases (type-alias indirection, schema-lookup miss for
`runtime_type_name`) through concrete-FieldType inheritance. The two
remaining fall-throughs at `:953/982` are documented as "shouldn't
happen for valid struct types". **(b) ERROR.** Replace with structured
compile error E#### naming the schema-lookup failure; if the schema is
genuinely missing for a non-alias non-base type, the prior compilation
phase should have caught it.

### §4.D.5 — `type_tracking.rs:1049` untyped `register_inline_object_schema` (Class (a))

`register_inline_object_schema(field_names)` constructs an all-`Any`
schema. The typed sibling `register_inline_object_schema_typed(fields:
&[(&str, FieldType)])` exists. **(a) PROPAGATE.** Deprecate the
untyped variant; require callers to pass typed fields. Audit all
callers to surface unresolved element types as structured errors at
the call site (W17.2 closure-wave §8 territory).

### §4.D.6 — `statements.rs:1485` + `comptime.rs:479` `__mod_*` synthetic export schemas (Class (d))

Module-export carrier-tier — the parallel-`field_kinds` track at
W17-comptime-vm-dispatch §2.7.26 carries the concrete `Ptr(HeapKind::ModuleFn)`
kind. ALLOWED via named exception class `MODULE_EXPORT_PREDECLARED_SCHEMA`.
The §5 verification pass whitelists schema names matching `__mod_*`.

OR strengthen by introducing `register_predeclared_kinded_schema(fields:

SURFACE-AND-STOP item §9.B.2.

### §4.D.7 — `helpers.rs:4901` generic-container annotation lowering (Class (a) candidate)

`"HashMap" | "Map" | "Result" | "Option" | "Set" => FieldType::Any` —

## §5 Verification-pass placement recommendation

**Placement.** Immediately after the bytecode-compilation second pass
completes (`crates/shape-vm/src/compiler/mod.rs` post-`compile_program`
boundary), but before the JIT registration phase. This is the
post-inference-output boundary the user 2026-05-18 binding targets.

**Mechanism.** A new module
`crates/shape-vm/src/compiler/post_inference_verify.rs` exposing
`verify_no_post_inference_any(program: &BytecodeProgram) ->
Result<(), Vec<SemanticError>>`:

1. Walk `program.type_schema_registry.by_name.values()`.
2. For each `TypeSchema`:
   - If schema name matches a named-exception whitelist (`Row`,
     `FrameState`, `VmState`, `ModuleState`, `CallPayload`, `__mod_*`,
     `__predecl_*`, annotation-handler ctx schema names, enum payload
     schemas via `is_enum()`), skip.
   - Else, for each `FieldDef` whose `field_type == FieldType::Any`:
     emit a structured `SemanticError` with code `E####` (TBD;
     candidate `E0900` — "post-inference FieldType::Any in user-facing
     schema") naming the schema + field.
3. Collect all errors; return `Err(Vec<SemanticError>)` if any.

**Wiring.** Call site in
`crates/shape-vm/src/compiler/compiler_impl_reference_model.rs` or
`compiler/mod.rs::Compiler::compile` final tail (after the post-pass
MIR analyses + dead-fields cross-reference at `compiler_impl_reference_model.rs:1200-1234`).

**Named-exception whitelist** (codified per §4.D dispositions):

```rust
const POST_INFERENCE_ANY_EXCEPTION_SCHEMAS: &[&str] = &[
    "Row",                  // §4.D.11
    "FrameState",           // §4.D.15
    "VmState",              // §4.D.15
    "ModuleState",          // §4.D.15
    "CallPayload",          // §4.D.15
];
const POST_INFERENCE_ANY_EXCEPTION_PREFIXES: &[&str] = &[
    "__mod_",               // §4.D.6
    "__predecl_",           // §4.D.12
    "__annotation_ctx_",    // §4.D.10 (introduce convention)
];
```

Plus the dynamic rule: schemas where `is_enum()` is true skip
`__payload_*`-named fields (§4.D.14).

**Test coverage** required at W17.2 landing:

- Negative: a user `type T { x: Any }` (currently parses to
  `FieldType::Object("Any")` per `helpers.rs:type_annotation_to_field_type`;
  this audit also recommends explicit `Any` as a parse error per §4.D.8).
- Negative: `let x = { f: someUntypedExpr }` — surfaces via §4.D.3
  fallback before reaching the verification pass; verification pass
  acts as the safety net.
- Positive: each named-exception class passes (Row instance, frame
  state introspection, module export call, predeclared schema call).

## §7 Possible `FieldType::Any` → `FieldType::Intermediate` rename

**Trade-off surface (SURFACE-AND-STOP §9.B.4).**

**Pro:**
- Makes the inference-intermediate / post-inference-output boundary
  explicit in the variant name. A grep for `FieldType::Intermediate`
  at any post-inference site is immediately suspect.
- Disambiguates from the deleted `SlotKind::Dynamic` /
  `KindedSlot::any()` shape — `Intermediate` clearly means "during
  inference"; `Any` historically meant "dynamic at runtime" (the
  deleted NaN-boxing rationalization).
- Mirrors Rust's `Type::Variable(TypeVar::fresh())` discipline at the
  schema layer — the schema-side equivalent of an unresolved type var.

**Con:**
- High blast radius — 94 lines / 17 files touched at HEAD, plus
  external doc + ADR-006 references + the deleted-form regex
  (`FieldType::Any` would be reborn under a new name, which the
  Forbidden Patterns §Renames-to-refuse-on-sight broader-family regex
  could refuse on sight if framed wrong).
- The 5 named-exception classes (`Row` / VM-state / `__mod_*` /
  `__predecl_*` / annotation-handler ctx) carry `FieldType::Any` at
  STORAGE time, not at inference time. Renaming would force a SECOND
  variant `FieldType::CarrierTierAny` for these, doubling the schema
  surface.
- `FieldType::Any` is already encoded into the wire format
  (`FIELD_TAG_ANY = 8` at `typed_object_ops.rs:48`) and the
  `to_native_kind` refusal arm at `field_types.rs:184`. Wire-format
  rename would be a snapshot-compat break.

**Recommendation: DO NOT RENAME.** The §5 verification pass + §6
CLAUDE.md extension provide the boundary enforcement without the
rename's blast radius. The rename's value (explicit-in-variant-name
boundary) is duplicated by the verification pass + whitelist
(explicit-in-named-exception-class boundary), and the verification
pass costs less.

If the supervisor disagrees (SURFACE-AND-STOP §9.B.4 ratify), the
rename would partition as W17.4 closure-wave — a single high-LoC
mechanical change after W17.2 + W17.3 land the verification pass +
per-site fixes.

## §9 SURFACE-AND-STOP items requiring supervisor architectural ratify

### §9.A ADR-006 amendments needed

**§9.A.1 — ADR-006 §2.7.26 carrier-exception list codification.**

The audit recommends extending §2.7.26 (W17-comptime-vm-dispatch) to
explicitly name the FIVE post-inference-`Any` exception classes
(`Row` / VM-state introspection / `__mod_*` / `__predecl_*` /
annotation-handler ctx / enum `__payload_*`). The amendment binds the
parallel-`field_kinds` track requirement to each class.

Estimated amendment LoC: ~40 lines. SURFACE-AND-STOP for supervisor
ratify; landed at W17.2-A close gate as the ADR companion to the
verification pass.

### §9.B Architectural decisions

**§9.B.1 — `FieldType::Option(Box<FieldType>)` variant introduction
(W17.2-B disposition (a) vs (b)).**

The §4.D.1 disposition recommends (a) PROPAGATE — introduce
`FieldType::Option(Box<FieldType>)`. Alternate disposition (b) ERROR
treats reaching `semantic_to_field_type` with unresolved Optional as
itself a compile error; this requires upstream inference to never
defer Optional resolution.

Trade-off: (a) preserves heterogeneous-discriminated-union as a
first-class schema concept (mirrors the §4.D.14 enum-payload
exception); (b) forces strict pre-resolution at the inference layer
(may surface as harder error messages for legitimate Option<T> chains
where T is itself inferred).

Supervisor ratify required before W17.2-B starts.

**§9.B.2 — `register_predeclared_kinded_schema(fields: &[(String,
NativeKind)])` introduction (W17.2-A § §4.D.6 alternate).**

Strengthening the predeclared-schema registrar to capture concrete
kinds at schema-construction time (instead of relying on the
parallel-`field_kinds` track populated at storage construction)
would tighten the §2.7.5 stamp discipline. Schema-side stays
`FieldType::Any`; the new API binds the kind alongside.

Trade-off: stronger boundary (kind known at compile time, not
storage construction time); extra API surface; existing
W17-comptime-vm-dispatch §2.7.26 path already works without it.

Supervisor ratify required to commit to the new API in W17.2-A scope
vs. defer to W17.5.

**§9.B.3 — `helpers.rs:4901` generic-container fallback disposition
(W17.2-C § §4.D.7 (a) vs TRANSITIONAL).**

Two valid dispositions for the 5-name container exception:

- (a) PROPAGATE — introduce per-container `FieldType` variants
  (`HashMap`, `Set`, `Option`, `Result`, `Map`). Schema surface grows
  by 5 variants. Wire format extends.
- TRANSITIONAL — narrow the fallback to exactly these 5 named
