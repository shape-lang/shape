## §1 Empirical repros at HEAD

### Repro1 (aliased push — SEGFAULT)
```shape
var data: Array<int> = [1, 2, 3]
let alias = data    // ← refcount bumps to 2; aliased
data.push(4)         // ← post-alias push triggers JIT crash
print(data)
print(alias)
```

| Tier | last-line | ec | Behavior |
|---|---|---|---|
| `--mode vm` | (correct array display) | 0 | Both prints emit `[1, 2, 3, 4]` (VM shares heap object; both view the mutation) |
| `--mode jit` | (core dumped) | **139** | SIGSEGV at `jit_v2_array_push` FFI entry point |

### Repro2 (non-aliased push — PASS)
```shape
var data: Array<int> = [1, 2, 3]
data.push(4)         // ← no alias; refcount stays 1
print(data)
```

| Tier | last-line | ec |
|---|---|---|
| `--mode vm` | `[1, 2, 3, 4]` | 0 |
| `--mode jit` | `[1, 2, 3, 4]` | 0 |

**Conclusion:** SEGFAULT manifests EXCLUSIVELY when receiver refcount > 1 + mutated via `.push()` under JIT. Removing the alias-binding line makes both tiers pass cleanly.

## §2 JIT lowering map

**Primary crash site:** `crates/shape-jit/src/mir_compiler/v2_array.rs::compile_typed_array_method` (lines ~470-809).

**Push arm:** lines ~591-606.

The bug: `self.read_place(receiver)?` loads the array pointer at line ~598, then immediately emits the FFI call `jit_v2_array_push(arr_ptr, ...)` at line ~601 with NO refcount check between them.

**FFI layer:** `crates/shape-jit/src/ffi/v2/mod.rs:562` — `jit_v2_array_push(arr_ptr, ...)` receives the pointer and calls `TypedArray::push` unconditionally.

**Underlying push:** `crates/shape-value/src/v2/typed_array.rs:149-159` — `TypedArray::push` also has no refcount check; assumes the caller verified exclusive ownership.

## §3 Root cause

**Missing refcount-guard before JIT inline push mutation.**

The JIT inlines `TypedArray::push` without checking whether the receiver's refcount > 1. When the receiver is aliased (refcount > 1), the JIT-loaded pointer is no longer exclusive: during deoptimization or JIT deopt-map construction (or any concurrent operation that the JIT codegen assumed couldn't happen on this pointer), the original array may be freed or reallocated, leaving the JIT-loaded pointer dangling → SIGSEGV when dereferenced inside `TypedArray::push`.

The VM doesn't crash because the VM dispatch in `executor/objects/array_basic.rs` (or similar push-handler) reads refcount via the typed-Arc carrier API and falls through to a clone-on-write path. The JIT, which inlines operations at codegen time, doesn't model this invariant — it assumes "I read the pointer, I own it for the duration of the mutation," which holds for refcount=1 paths but not for aliased paths.

## §4 Fix recipe — Medium scope (0.5-1 session)

### Step 1 — `crates/shape-jit/src/mir_compiler/v2_array.rs` push arm (~20 LoC)
After `read_place(receiver)?`, emit a refcount load (HeapHeader refcount at offset 0 per §2.7.5.1 stamp invariant) + compare to 1. If > 1, call `jit_clone_array_if_shared(arr_ptr) -> *mut TypedArray<T>` FFI wrapper to clone-on-write + rebind. Then proceed to `emit_v2_array_push_call(new_arr_ptr, ...)`.

### Step 2 — `crates/shape-jit/src/ffi/v2/mod.rs` (~10 LoC)
Add `#[no_mangle] pub extern "C" fn jit_clone_array_if_shared<T>(arr: *mut TypedArray<T>) -> *mut TypedArray<T>` wrapper. Internally: `if header.refcount > 1 { Arc::increment_strong_count + TypedArray::clone + return new pointer } else { return arr }`. Mirror the existing VM-side CoW shape.

### Step 3 — tests (~30 LoC)
- repro1 passes JIT (no crash, both prints emit `[1, 2, 3, 4]`)
- repro1 alias still sees the SHARED-thru-CoW mutation OR sees the pre-mutation snapshot (whichever VM semantics dictate — confirm against VM behavior; the audit shows VM emits identical arrays so CoW shares the mutation post-clone)
- repro2 still works (non-aliased path unchanged)
- smoke s1-s5 5/5 VM == JIT preserved

## §6 Surface-and-stop fallback (if scope expands to L)

**Feasible: YES, trivial.** At the push arm in `v2_array.rs`, check if receiver's refcount can be statically proven = 1 (e.g., no `let alias = ...` upstream in the same scope). If not provable, return `Ok(None)` from `compile_typed_array_method` to deopt to interpreter. Result: repro1 runs in the VM interpreter (correct, slower); repro2 still JIT (fast).

This is the divergence-elimination minimum per the Group 1 unconditional-gating binding — eliminates the SEGFAULT (memory-unsafety) without taking on the full refcount-CoW codegen scope.

**Recommended path:** Step 1+2 fix (full refcount-aware codegen) since it's M-scope and matches the canonical CoW invariant. Use the fallback only if Step 1+2 turns out to be larger than estimated.

## §7 Defection-attractors refused

- "Resurrect `Arc<TypedArrayData>`" — refused. W12 strict-typing close deleted this; v2-raw `*mut TypedArray<T>` is the canonical carrier.
- "Emit CoW in MIR lowering" — refused. MIR operates on static types, not runtime refcount; CoW belongs at the runtime-tier dispatch boundary.
- "Bool-default refcount probe" — refused. Refcount is a u32 at offset 0; read directly, dispatch directly.
- "Decode kind from bits" — refused. Kind is stamped at compile time (§2.7.5); the JIT already knows the receiver kind.
- "Add a feature flag to gate the refcount check" — refused (§Forbidden rationalizations #8).
